## 1. 文档职责

本文固定 XuanXue 第一版首页与每日内容的目标产品行为，回答：

1. 首页怎样让普通用户理解产品，而不是把工具堆在一起；
2. 游客、有账号但无记录、已有真实记录的用户分别看到什么；
3. “今日玄机、今日命签、今日穿衣”怎样退出或重构；
4. “今日事实、节气一读、今日观照”分别依据什么、不能表达什么；
5. 有明确目标和兴趣浏览的用户怎样进入已开放工具；
6. 来源、规则、限制和体验版状态怎样逐层展示；
7. 时间、跨日、失败、移动端、无障碍和验收证据怎样统一。

本文是产品和数据契约，不是实施计划，也不表示当前页面已经符合本文。本文批准后：

- 不自动授权修改产品代码、测试、数据库或部署；
- 不表示历法、节气文化资料或现有命签文本已经完成来源核验；
- 不表示候选工具已经批准公开；
- 不表示第一版、预览版本或 P5 阶段已经完成；
- 不授权生成包含首页与多个工具的一次性大型实施计划。

## 3. 当前实现问题与处置依据

当前首页已经能够运行，但它同时承担宣传页、每日内容、工具目录和登录后个人首页，存在以下已确认问题：

1. 访客页与登录后首页是两套差异较大的内容结构，用户难以形成稳定认知；
2. “知天命”“中式命理，一应俱全”等文案超过产品能够证明的范围；
3. 访客主按钮把登录作为探索前置条件，与游客可直接体验的目标冲突；
4. “今日玄机”中的年份、时区和节气附近日期表达存在边界风险；
5. “今日命签”在页面加载时自动产生，同日所有用户由日期映射到相同内容，却容易被理解为个人命签；
6. 当前命签目录和传统引注尚未完成逐条来源核验；
7. “今日穿衣”使用项目自行拼接的五行颜色规则，却以“宜着、避”等行动性语言展示；
8. 登录后问候、每日模块和工具墙组合成高密度双栏，小屏存在标题挤压和横向溢出风险；
9. 原“注／算法溯源”组件具有固定最小宽度、展开裁剪和键盘关闭问题；
10. 候选、内部审核和公开工具容易因页面存在而被放进同一个工具目录；
11. 最近记录、加载失败和真正空状态之间缺少清楚区别；
12. 每日内容中的事实、传统文化材料、项目编写内容和随机互动没有形成稳定边界。

P1 审计与浏览器验证继续作为历史证据；本文负责固定整改后的目标行为，不倒写当前实现已经完成整改。

## 4. 首页目标与非目标

### 4.1 第一版目标

首页必须让普通用户在不预先理解专业术语的情况下完成四件事：

1. 理解 XuanXue 是传统文化互动探索产品，不是确定性预测服务；
2. 无需登录即可阅读可靠的每日公共内容；
3. 可以按自己的意图探索，也可以直接选择已经开放的方法；
4. 登录并主动保存过内容后，可以继续查看真实探索记录。

### 4.2 第一版非目标

首页第一版不负责：

- 预测用户今日事业、感情、财运或健康；
- 根据昵称、出生资料或历史记录生成个人“今日运势”；
- 催促用户建立或完善本人资料；
- 展示档案完整度、功能解锁百分比或成长等级；
- 自动抽签、自动保存、自动更新本人资料；
- 展示未批准公开的工具、空壳卡片或虚假上线日期；
- 建设日记、回答保存、社交分享、推荐算法或 AI 解读；
- 为追求全屏视觉效果重做墨韵设计语言；
- 使用免责声明为无依据内容兜底。

## 5. 首页信息架构

第一版采用“稳定公共发现空间 + 真实个人延续入口”的混合首页。登录前后使用同一套页面骨架，不再维护两张互不相干的首页。

目标语义顺序为：

```text
顶部导航
↓
产品第一屏
↓
继续探索（仅登录且确有已保存记录时出现）
↓
今日一页
  ├─ 今日事实
  ├─ 节气一读
  └─ 今日观照
↓
按目标探索
↓
直接选择方法
↓
透明性与版本入口
  ├─ 内容与规则
  ├─ 来源目录
  ├─ 数据与隐私
  └─ 体验版说明
```

桌面端可以使用多栏视觉编排，移动端必须保持上述 DOM 阅读顺序并回流为单列。没有真实内容的条件区块不保留空白占位。

## 6. 产品第一屏

### 6.1 目标文案

第一版目标文案为：

> **传统文化互动探索**
>
> # 看懂传统规则，再开始自己的探索
>
> 从历法事实、传统分类与文化互动出发，在清楚的来源和边界中，了解这些方法怎样形成，也整理自己的思考。
>
> 看得懂 · 说得清 · 查得到

主要操作为：

- `按目标开始`：定位到“按目标探索”；
- `直接选择方法`：定位到“直接选择方法”。

两个操作都是页面内导航，不把登录作为前置条件。登录入口独立存在于顶部导航。

### 6.2 常驻边界

第一屏之后以可读但不过度抢眼的方式说明：

> 传统文化内容不等于科学预测，结果不用于医疗、法律、投资等重要决定。

该说明不能为前文的确定性承诺兜底。页面自身仍必须删除或阻断不合格内容。

### 6.3 退出文案

首页和相关入口不再使用：

- 知天命；
- 一应俱全；
- 精准测算；
- 揭秘未来；
- 专属运势；
- 登录解锁全部功能；
- 其他暗示必然预测能力或功能已经全部成熟的表达。

首页不根据昵称或档案生成“懂你”的欢迎语。登录状态只用于展示真实账号操作和真实保存记录。

## 7. “今日一页”公共内容

“今日一页”是首页每日公共内容的总标题，下设三个边界不同的区块。三者不读取本人档案，不构成个人命理结果，也不保存为探索历史。

### 7.1 统一今日快照

三个区块必须共享同一份显式今日上下文：

| 字段                  | 作用                                        |
| --------------------- | ------------------------------------------- |
| `asOfDate`            | 北京时间下的公历日期，格式为 `YYYY-MM-DD`   |
| `timeZone`            | 固定为 `Asia/Shanghai`                      |
| `generatedAt`         | 本次快照形成的 UTC ISO 时间戳               |
| `calendarRuleVersion` | 历法与节气计算采用的规则版本                |
| `contentSetVersion`   | 节气文章和观照题库采用的内容目录版本        |
| `dayKey`              | 由 `asOfDate + timeZone` 形成的稳定日期标识 |

页面不得让三个组件分别调用设备当前时间。设备时区不得改变产品中的“今日”。页面显示：

> 时间基准：北京时间

历法依赖库是工程实现，不自动成为历法权威。规则和测试样例仍须回链正式标准、官方历书或经过审核的资料。

### 7.2 今日事实

“今日事实”只展示可复算、可核对的日期与历法信息：

- 公历日期；
- 星期；
- 农历日期及闰月状态；
- 按本区块明确口径形成的干支年、月、日；
- 当前节气阶段；
- 下一节气及按北京时间计算的相距天数；
- 快照时间基准和历法规则版本入口。

边界规则：

1. 农历干支年使用本文及后续规则目录明确的农历纪年口径；
2. 八字工具采用的立春、节气时刻或其他边界属于八字领域规则，不能静默搬到首页；
3. 只有实际进入节气的准确日期才显示“今日进入某节气”；
4. 删除“节气前后两天都算今日节气”的宽松徽章；
5. 不展示黄历宜忌、冲煞、神煞、幸运色、幸运数字、个人运势、天气或定位信息；
6. 不把干支、五行或节气扩写成当天行动命令。

若农历或节气计算失败，继续展示已确认可用的公历日期和星期，并明确显示“农历信息暂不可用”或对应失败状态，不使用上一次成功值或猜测值填补。

### 7.3 节气一读

“节气一读”提供当前节气的短篇文化理解，不建设 365 条每日断语。

第一版内容范围为：

- 24 个节气各一份基础说明；
- 每个节气至少一项经过来源核验的文化材料；
- 必要的年代、地域、版本和适用语境；
- 项目自行撰写的通俗解释；
- 可选的一条非预测性观察提示。

内容目录至少记录：

| 字段               | 说明                             |
| ------------------ | -------------------------------- |
| `contentId`        | 稳定内容标识                     |
| `solarTermId`      | 对应节气标识                     |
| `knowledgeNature`  | 历法事实、历史文化资料或项目整理 |
| `sourceReferences` | 直接支持该内容的来源标识         |
| `sourceStatus`     | 来源核验状态                     |
| `regionContext`    | 地域适用范围                     |
| `timeContext`      | 年代或历史语境                   |
| `plainExplanation` | 项目自行撰写的普通语言说明       |
| `limitations`      | 不能推出的结论                   |
| `contentVersion`   | 内容版本                         |

同一节气存在多条已批准内容时，可以按“节气 + 日期 + 内容目录版本”稳定轮换，并明确称为内容轮换；不得称为随机推荐或个性化内容。

气候物候、农事和习俗不得写成全国、全年代都相同的普遍事实。没有通过核验的文化条目不公开；可以只保留今日事实，不能临时从互联网拼接内容补位。

### 7.4 今日观照

“今日观照”是用户主动选择主题后的自我整理问题，不是档案生成、命理预测或通用鸡汤。

第一版提供四个关注方向：

- 学习与事务；
- 关系与表达；
- 自我状态；
- 一个决定。

初始状态不替用户选择方向，也不展示伪个性化问题。用户选择后，系统按“日期 + 用户所选方向 + 题库版本”稳定选择一条经过人工审校的问题。用户可以更换方向。

题库内容必须：

- 使用开放、中性、不预设事实的提问；
- 不假设用户在工作、求学、恋爱、结婚或面临某类事件；
- 不引用出生资料、历史结果或昵称；
- 不输出吉凶、运势或行动命令；
- 不声称来自古籍，除非该句确有可核验出处且按文化材料治理；
- 清楚标识“问题由项目编写，用于自我整理，不是命理预测”。

第一版不提供自由文本回答框，不保存选择或答案，不形成日记，不把选择写入内容偏好，也不调用 AI。

### 7.5 跨日行为

页面跨过北京时间零点时：

- 不在用户阅读中突然替换三个区块；
- 在页面重新获得焦点或检测到日期变化时显示“已进入新的一天，更新今日内容”；
- 用户确认后一次性刷新整个今日快照；
- 不允许日期已经更新而节气文章或观照问题仍属于昨天；
- 昨天的缓存不得伪装成今天的内容。

### 7.6 分层失败

三个区块彼此隔离失败：

- 农历失败不删除可用公历事实；
- 节气文章失败不删除今日事实，也不展示昨天的文章；
- 观照题库失败显示“今日观照暂时无法加载”，不随机拼句；
- 今日快照整体失败显示可重试状态，不伪装成空内容；
- 错误日志只记录错误类别、日期标识和规则／内容版本，不记录本人资料。

## 9. 首页发现入口

### 9.1 双入口结构

首页同时服务目标明确和兴趣驱动的用户：

1. `按目标探索`：先说用户想做什么；
2. `直接选择方法`：直接展示已经批准公开的方法名称。

两种入口必须读取同一个工具状态目录，不分别维护可见工具名单。

### 9.2 按目标探索

第一版目标结构为：

| 用户意图             | 去向                                           | 边界                     |
| -------------------- | ---------------------------------------------- | ------------------------ |
| 我想看懂今天         | 定位到“今日一页”                               | 不进入个人运势           |
| 我想认识自己         | 展示生肖、太阳星座、八字基础等已开放方法的差异 | 不生成跨工具综合人格结论 |
| 我想体验一种传统方法 | 只在至少一个对应候选工具已经批准公开时出现     | 没有合格工具时整项隐藏   |

首页不提供“测事业、测姻缘、测财运、测健康”等生活结果入口。系统没有足够事实和证据支撑这些承诺，也不能通过用户点击主题推导现实结论。

一个目标下没有已开放去向时，该目标整体不渲染，不展示“敬请期待”或不可点击卡片。

### 9.3 直接选择方法

此区域只展示工具状态同时满足下列条件的方法：

- `reviewStatus = approved`；
- `exposure = public`；
- `computePolicy = enabled`；
- 历史策略与工具合同一致。

每张方法卡片必须让普通用户直接知道：

- 这是什么；
- 可以看到什么；
- 需要提供哪些信息；
- 内容属于事实计算、传统分类、文化资料还是文化互动。

第一版排序按理解成本和输入成本，而不是开发时间或营销优先级。轻量入口在前，深度入口在后。卡片不使用评分、准确率、虚构推荐理由、锁定态或未审核功能占位。

### 9.4 第一版核心映射

| 方法     | 首页说明重点                                   | 输入提示                     |
| -------- | ---------------------------------------------- | ---------------------------- |
| 生肖文化 | 根据出生日期了解传统生肖分类及其文化含义       | 出生日期                     |
| 太阳星座 | 根据出生日期了解西方太阳星座分类；不是完整星盘 | 出生日期                     |
| 八字基础 | 查看出生信息形成的基础排盘和术语解释           | 出生日期、时间精度、出生地区 |

该表表达第一版目标范围，不表示三项当前代码已经通过全部公开验收。候选工具只有在独立契约、来源和公开门槛通过后才能加入。

## 10. 游客、登录与个人延续

### 10.1 登录边界

首页采用“游客先体验，保存时再登录”：

- 游客可以查看首页、来源说明和所有已开放工具；
- 游客可以按工具合同临时填写资料并生成结果；
- 游客输入默认只存在于当前页面，不进入服务器档案和历史；
- 登录入口可以常驻导航，但不反复催促；
- 保存本人资料、保存允许保存的结果、查看历史和管理个人数据时才要求登录；
- 登录成功不触发自动保存、自动计算、自动迁移草稿或自动更新档案；
- 注册时完成必要的服务与隐私确认；
- 工具处理出生信息前进行与当前用途对应的简明告知；
- 保存本人资料和保存结果分别主动确认，不能由一次隐私政策确认替代。

首页可以使用以下说明：

> 无需登录即可体验。登录后可主动保存本人资料和部分探索结果。

涉及未满十四周岁、敏感个人信息和保存操作时，继续执行用户档案与数据生命周期规范，不在首页创造宽松例外。

### 10.2 不使用抽象个人区名称

用户界面不使用“我的书案”“我的探索”“知己阁”等需要解释的总名称。内部可以把相关能力称为个人延续区，但界面按用户任务直接命名：

- `继续探索`；
- `本人资料`；
- `探索记录`；
- `数据与隐私`。

顶部账号入口可以简写为 `我的`，展开后显示上述明确目的的入口。

### 10.3 首页状态

| 状态           | 首页行为                                           |
| -------------- | -------------------------------------------------- |
| 游客           | 不渲染空的个人区域；在工具区后轻量说明登录保存价值 |
| 已登录但无历史 | 不渲染“继续探索”空卡；直接进入今日与发现内容       |
| 已登录且有历史 | 第一屏后展示“继续探索”，最多三条真实最近记录       |
| 历史加载失败   | 显示“探索记录暂时无法加载”和重试，不伪装成没有记录 |

最近记录只展示真实保存的工具名称、安全摘要、保存时间和查看入口，不根据历史猜测用户当前关注，也不生成 AI 或模板摘要。

本人资料不在首页展示出生日期、时辰、地区或完整度。管理入口位于“我的”菜单；具体工具需要字段时再按规范提示。

## 11. 三级透明结构

原“注／算法溯源”按钮和浮层退出首页及公开工具。首页采用三级渐进透明结构。

### 11.1 第一级：内容性质

内容旁使用简洁、始终可见的标签。首页标签映射到通用内容治理模型：

| 用户可见标签 | 通用性质                     |
| ------------ | ---------------------------- |
| 历法事实     | 计算结果／历法或天文计算事实 |
| 传统规则     | 传统分类                     |
| 文化资料     | 历史文化资料                 |
| 项目整理     | 项目实现规则或编辑性内容     |
| 文化互动     | 非现实预测的互动内容         |

来源状态与内容性质分开记录。`unverified` 或 `no_source` 不能因为贴上标签就在首页公开文化断语或个人解释。

### 11.2 第二级：查看依据与限制

每个需要解释的区块提供清楚的文字入口：

> 查看依据与限制

展开后在正常页面文档流中显示：

- 内容怎样形成；
- 使用了哪些输入或日期上下文；
- 哪些部分可以复算；
- 哪些部分属于传统资料或项目整理；
- 当前限制与不能推出的结论。

不得恢复单字“注”按钮、固定宽度气泡、悬浮说明、遮挡正文的弹窗或固定 `max-height` 展开动画。

### 11.3 第三级：完整规则与来源

长内容进入稳定页面，至少包括：

- 规则名称、步骤与版本；
- 原始出处或正式标准；
- 作者或责任机构、版本、出版信息和具体位置；
- 经核验的稳定链接；
- 项目采用方式及自行选择部分；
- 来源状态、人工审核状态和修订记录；
- 流派差异、地域和年代边界。

古籍没有可靠公开链接时使用版本、卷章和页码定位；国家标准、官方历法和机构资料可以提供直接链接。搜索结果页、无关首页或商业网站汇总不能冒充权威来源。

### 11.4 页脚入口与体验版表达

页脚固定提供：

- 内容与规则；
- 来源目录；
- 数据与隐私；
- 体验版说明。

当前运行环境内部状态仍为 `public_preview`。普通用户可见文案使用：

> 当前为体验版本，部分规则与内容持续核验。

该状态不放在首页顶部制造警报，也不隐藏于不可发现的位置。它不表示当前产品已经发布 `0.1.0-preview.1`。

## 12. 模块边界

首页继续处于 Nuxt 模块化单体中，不新建 Spring Boot 服务、微服务或 AI 服务。实现应按职责拆分，但不为目录整齐创建空抽象：

| 单元         | 单一职责                         | 不负责                       |
| ------------ | -------------------------------- | ---------------------------- |
| 首页编排     | 按本文顺序组合区块和状态         | 计算历法、直接读取数据库     |
| 今日上下文   | 形成北京时间今日快照和跨日信号   | 编写文化解释                 |
| 历法事实     | 根据显式上下文形成可复算事实     | 生成运势和生活建议           |
| 节气内容目录 | 返回已批准的节气文化内容         | 在线抓取临时文章             |
| 观照题库     | 按日期、方向和版本稳定选择问题   | 读取档案、保存回答、调用 AI  |
| 工具状态目录 | 控制目标入口、方法卡片和路由能力 | 在页面内复制第二套状态       |
| 最近探索     | 读取真实历史安全摘要             | 猜测用户兴趣、静默重算旧结果 |
| 透明性入口   | 映射内容、规则和来源             | 把未核验来源包装成已验证     |

工具状态目录和内容目录应由客户端与服务端共享或通过稳定合同取得；页面不得把业务状态散落在模板条件中。

## 13. 加载、空状态与错误

首页每个异步区块具有独立状态，不能用一个全页 loading 掩盖所有内容：

| 区块     | 空状态                         | 失败状态                               |
| -------- | ------------------------------ | -------------------------------------- |
| 今日事实 | 不应合法为空                   | 保留可用部分并说明具体失败             |
| 节气一读 | 无已核验内容时不展示文化正文   | 明确暂不可用，不使用昨天内容           |
| 今日观照 | 未选择方向时显示方向选择       | 题库失败时说明并允许重试               |
| 继续探索 | 无记录时整个区块不渲染         | 明确加载失败并允许重试                 |
| 发现入口 | 没有合格工具的目标或分类不渲染 | 状态目录失败时不展示未经确认的缓存列表 |

错误信息必须说明用户是否可以重试，不能只通过短暂通知条显示。恢复后只更新对应区块，除非错误影响统一今日快照。

## 14. 移动端与无障碍门槛

### 14.1 页面回流

- 在 320、360、390、414 CSS 像素宽度完成整条首页路径；
- 普通内容只允许页面纵向滚动；
- 标题、日期、标签、来源、长网址和按钮自然换行；
- 不通过固定宽度、固定高度或绝对定位容纳正文；
- 依据内容展开后把后续内容自然向下推开；
- 只有无法纵向表达的图表或表格可以在组件内部横向滚动，首页普通内容没有此例外需要；
- 不使用全局 `overflow: hidden` 掩盖溢出。

### 14.2 缩放与文字

- 不禁止双指缩放，不设置限制用户缩放的视口参数；
- 文字放大至 200% 时不截断、覆盖或丢失功能；
- 验证等效 320 CSS 像素宽度和 400% 页面回流；
- 针对 P1 已发现的自由缩放、浮层和重叠问题，增加 500% 浏览器压力测试；
- 500% 是项目回归强化项，不称为 WCAG 的正式数值要求。

### 14.3 操作与语义

- 常规按钮和图标按钮采用至少 44×44 CSS 像素的项目触控目标；
- 相邻控件保留足够距离；
- 每页具有唯一主标题和顺序合理的区块标题；
- 所有功能使用正确的链接或按钮语义并可通过键盘完成；
- 焦点清晰可见，菜单支持 Escape 关闭并把焦点还给触发控件；
- 展开控件具有可感知的展开状态和受控区域关系；
- 加载、失败、跨日和刷新结果通过适当状态区域宣布；
- 图标不单独承担含义，颜色不是状态的唯一表达；
- 动画遵循 `prefers-reduced-motion`。

## 15. 验收合同

首页实现后必须依次通过工程验证、Codex 内置浏览器验收和用户真实设备验收。缺少任一层，不得标记 `Accepted`。

### 15.1 自动化与工程验证

至少覆盖：

- 北京时间 23:59、00:00 及与 UTC 日期不一致的场景；
- 三个每日区块共享同一 dayKey；
- 农历、节气内容、观照题库和历史接口分别失败；
- 未选择观照方向时不生成问题；
- 同一日期、方向和内容版本得到稳定问题；
- 观照内容不读取档案、不保存选择或答案；
- 工具状态目录决定两个发现入口，未批准工具不出现；
- 游客可进入公开工具，登录不触发自动保存；
- 没有历史时不渲染空的“继续探索”；
- 现有“今日命签、今日穿衣、注”不再从首页公开渲染；
- 禁止文案、用户可见评分和伪个性化扫描；
- `git diff --check`、乱码检测、typecheck、test、lint 和 build。

### 15.2 Codex 内置浏览器验收

Codex 必须使用应用内置浏览器对真实运行页面执行自动化交互与视觉复验，不得只依据执行器自报、组件测试或静态截图判断完成。

浏览器场景至少包括：

1. 游客从第一屏进入今日一页、按目标探索和直接选择方法；
2. 游客进入公开工具时不被无条件重定向登录；
3. 今日观照选择四个方向、切换方向和题库失败；
4. 查看依据与限制的展开、收起、键盘和焦点行为；
5. 登录但无历史、登录且有真实历史、历史加载失败；
6. 跨日提示和整体刷新；
7. 320、360、390、414 CSS 像素宽度的完整页面滚动；
8. 200% 文字缩放、400% 回流及 500% 已知问题压力测试；
9. 页面级横向溢出、文字重叠、不可关闭菜单、被遮挡按钮；
10. 控制台错误、失败请求和状态恢复。

Codex 验收记录至少保存：

- 被测提交或工作区状态；
- 本地地址、运行环境和测试日期；
- 浏览器、视口、缩放和登录状态；
- 测试数据是否为虚构测试数据及其授权边界；
- 每个场景的步骤、预期、实际结果和通过状态；
- 关键状态截图或等价可复核证据；
- 未通过项和未测试边界。

涉及创建、修改、保存或删除用户数据时，优先使用专用测试账号和虚构资料；使用用户真实数据前必须取得专门授权。

### 15.3 用户手动验收

Codex 浏览器验收通过后，由用户在至少一台真实手机上完成手动体验。最低路径包括：

- 从首页第一屏读到今日一页；
- 选择并切换今日观照方向；
- 展开依据与限制并返回；
- 使用按目标探索和直接选择方法；
- 打开、关闭顶部“我的”菜单；
- 双指缩放、纵向滚动和横竖屏切换；
- 在用户愿意的情况下验证登录前后状态；
- 确认没有文字重叠、页面自由横向滑动、按钮难点或内容难懂。

用户可以提出体验问题并要求返工。只有用户明确确认接受，路线图才可以把对应首页实施阶段标为 `Accepted`。

### 15.4 验收结论边界

- 自动化通过不等于来源核验通过；
- Codex 内置浏览器通过不等于真实手机体验通过；
- 用户认为视觉好看不等于规则真实；
- 文档批准不等于代码已经实施；
- 当前公网可访问不等于首页已经批准正式公开。
