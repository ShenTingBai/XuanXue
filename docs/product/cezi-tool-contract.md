# 测字工具产品、内容与领域契约

> 状态：Approved — 产品决策已经用户逐项确认
>
> 版本：1.0.1
>
> 最后更新：2026-09-06
>
> 适用范围：XuanXue 现有“测字占卜”退役、后续“了解一个字／一字观照”双轨候选的来源、内容、领域实现、页面、导出、测试与重新开放验收

## 1. 文档目的

本文固定 XuanXue 现有“测字占卜”的退役决定，以及后续“测字”双轨候选的产品、资料、娱乐内容、隐私和工程边界。

本文不是对现有代码、测试、来源声明或公开页面的背书，也不表示候选能力已经完成来源核验、权利审查、实现或公开验收。后续来源账本、字库、领域模块、页面、测试和实施计划不得绕过本文恢复笔画五行、81 数理、自动吉凶或个人命运预测。

本文中的“第一版”指本轮打磨形成的首个受治理候选版本。测字不是首个核心治理版本的必备能力，不得延迟生肖、太阳星座、八字基础、档案和首页的核心闭环。

## 2. 核心裁决摘要

1. 现有“测字占卜”退役，不再公开笔画五行、偏旁五行、81 数理、字形性格、事业感情和吉凶预测。
2. 页面总入口保留熟悉名称“测字”，不使用“测字占卜”。
3. 候选分为“了解一个字”和“一字观照”两条路径；事实资料、历史材料与娱乐内容必须分层，禁止混写。
4. “了解一个字”展示已核验的规范状态、读音、笔画、部首、结构、常用义、可选字形资料和历史案例。
5. “一字观照”是持续标注为娱乐内容的文字联想与自我提问，不是心理分析、现实判断或未来预测。
6. 一字观照输入为一个已支持汉字和一个可选固定主题；不接收完整问题、个人故事或自由主题。
7. 固定主题为随意看看、当下状态、学习与成长、工作与行动、人际相处、感情思考。
8. 主题只选择已审核的反思角度，不表示系统理解用户经历；全部文案保持身份、关系和生活状态中立。
9. 用户可以主动输入汉字，也可以从观照可用字库随机取字；随机机制不包装为天意、缘分或命定。
10. 未收录、资料冲突、含义歧义未治理或内容不完整时显式限制，不估算笔画、不默认独体、不自动转换、不使用通用模板补齐。
11. “了解一个字”“一字观照”“历史案例”分别采用能力状态；三类内容不要求相同覆盖数量。
12. 一字观照首轮公开候选至少包含 30 个字，每个字覆盖六个固定主题，每个主题至少两个固定角度。
13. 相同版本、汉字、主题和角度得到相同内容；“换个角度”按固定顺序切换，不重新计算运势。
14. 高风险字可以在事实路径中中性展示，但不能进入一字观照和随机字库。
15. 多音、多义或语义边界未治理的字可以查看完整事实资料，但第一版不进入一字观照。
16. 历史测字案例只供独立阅读，不参与当前用户的趣味内容；文学、笔记与可证历史事实分别标注。
17. 来源可信度与使用权限分别审核；只有内容来源和公开使用方式都通过的字段才能进入产品。
18. 第一版游客可用，不强制登录、不读取档案、不上传输入、不保存服务器历史、不写浏览器长期存储。
19. 导出只允许浏览器本地生成 PNG，导出前预览，不提供公开链接、二维码或社交平台直传。
20. 现有旧测字历史不迁移到新模型；在已批准的一次性数据库重建前不得由新页面恢复。
21. 候选继续采用 Nuxt 3 模块化单体，不新建 Spring Boot 后端、不拆微服务、不接入 AI。
22. 当前目标状态为 `reviewStatus = in_review`、`exposure = internal`、`computePolicy = blocked`、`historyPolicy = disabled`；各能力通过独立门禁后才可讨论受限公开预览。

## 3. 当前代码审计结论

### 3.1 当前实现位置

现有测字能力主要分布在：

- `pages/tools/cezi.vue`：登录围栏、单字输入、结果展示、来源说明、自动保存、历史恢复和 PNG 导出；
- `composables/useCezi.ts`：CJK 判断、笔画处理、五行映射、部首五行检测、结构推断和解释拼接；
- `constants/cezi.ts`：部首五行、字符五行、结构释义、81 数理、五行性格／事业／感情文案和结构吉凶；
- `tests/composables/useCezi.test.ts`、`tests/composables/useCezi-exhaustive.test.ts`：输入、样本结构、五行、吉凶和始终产生解释的行为测试。

### 3.2 当前算法实际行为

当前引擎不是一套已经核验的历史测字方法，而是以下内容的工程组合：

1. 从现有字典查询笔画；
2. 查不到笔画时按 Unicode 码位估算；
3. 按笔画尾数映射木火土金水；
4. 按 81 数理表或尾数回退生成吉凶；
5. 通过有限字符表和码位区间启发式推断字形结构；
6. 把五行、结构、性格、事业、感情和总结模板拼成个人化文案。

`constants/cezi.ts` 已把笔画尾数五行、尾数吉凶回退、结构启发式和综合模板标记为开发者合成。当前页面虽然展示来源说明，但这些引用没有直接证明上述组合属于《说文解字》《康熙字典》《易经》或传统测字规则。

### 3.3 现有测试不能证明真实性

现有测试主要证明：

- 常见样本能够返回非空结果；
- 返回对象具有笔画、五行、结构、吉凶和解释字段；
- 同一输入重复调用时结果稳定；
- 部分预设字符返回期望结构。

这些测试没有证明笔画来源、部首五行、结构寓意、81 数理和现实解释具有可靠依据。测试通过不等于来源通过，也不构成继续公开旧内容的理由。

### 3.4 现有页面问题

- 强制登录，但工具不需要任何个人档案字段；
- 生成后自动调用 `/api/divinations` 保存输入和完整结果；
- 旧历史能够恢复不再受支持的预测文案；
- SEO 继续宣传“解读运势和事物发展趋势”；
- 使用已经决定退役的悬浮 `MethodologyNote`；
- 人为延迟后显示“正在测字”，使本地模板查询看起来像复杂推演；
- 整页截图导出可能携带旧预测内容和不适合分享的展开区域。

因此现有页面、算法、常量和测试均为待退役实现。视觉外壳和通用导出能力只有通过逐项审查后才可复用。

## 4. 产品定位与命名

### 4.1 总入口

用户可见总入口固定为：

> 测字

副标题候选为：

> 认识一个汉字，也可以从中获得一次趣味联想。

不得使用“测字占卜”“一字窥天机”“命定之字”“测字断命”等暗示预测能力的总名称。

### 4.2 双轨入口

进入页面后先显示两张模式卡：

1. **了解一个字**：查看经过核验的笔画、部首、结构、常用义、字形资料和历史案例；
2. **一字观照**：从一个汉字和主动选择的主题出发，获得明确标注为娱乐内容的文字联想和自我提问。

“一字观照”标题旁始终显示 `娱乐互动` 或同义的明确性质标签。雅致名称不能替代内容性质披露。

### 4.3 用户价值

测字候选帮助用户：

- 先认识一个字的可验证资料；
- 理解历史上测字作为文化现象怎样使用字形、语境和联想；
- 在知道内容是娱乐生成的前提下，从一个字获得一次轻量自我观察；
- 随时查看资料、来源、生成方式和不能说明的内容。

它不帮助用户判断命运、吉凶、性格、关系结果、考试结果、事业成败、疾病、财务或其他现实结论。

## 5. 与产品总纲的关系

“了解一个字”属于公共文化与可验证资料；“一字观照”属于如实披露生成方式的轻量互动。两者共同体现 XuanXue 的核心边界：真实资料和娱乐内容可以并存，但每个用户可见单元必须清楚表明自己的性质。

测字不进入个人连续体验，不读取本人档案，不构建历史轨迹，也不向首页制造伪个性化“今日幸运字”。

## 6. 当前状态与公开围栏

### 6.1 四维状态

本文收口后的目标状态为：

```text
reviewStatus: in_review
exposure: internal
computePolicy: blocked
historyPolicy: disabled
```

含义为：

- 产品契约已经批准；
- 来源、权利、内容、实现和体验尚未完成；
- 首页、目录、导航、发现、推荐、最近使用和 SEO 不得宣传旧测字能力；
- 旧算法不能继续生成结果；
- 不继续写入或恢复测字服务器历史。

### 6.2 旧地址

候选隐藏期间，旧地址 `/tools/cezi` 进入统一状态页，只说明：

- 旧测字占卜内容已经停止；
- 新候选正在整理汉字资料、历史材料和娱乐内容边界；
- 当前不能计算、保存或导出；
- 没有承诺恢复日期。

页面仍能打开、旧测试仍能通过或服务器未主动宣传，都不表示可以绕过围栏。

## 7. 能力分层

每个汉字分别记录三种能力：

```text
basicFacts: unavailable | pending | conflict | verified
observation: unavailable | pending | approved
historicalCases: none | pending | available
```

- `basicFacts = verified` 才能进入“了解一个字”；
- `observation = approved` 才能进入“一字观照”和随机字库；
- `historicalCases = none` 是正常状态，不影响前两类能力；
- 任一能力不得从其他能力状态推断得出。

这三项是字级能力状态，不是 `sourceStatus` 或 `sourceReviewStatus`。例如 `basicFacts = verified` 只在所需基础字段逐条通过第 19、20 章的来源、人工审核和权利门禁后才能得到；不能用一个字级 verified 标签替代逐条来源记录。

基础资料可以覆盖更多汉字；一字观照只覆盖内容完整的子集；历史案例逐条通过、逐条出现。

## 8. 用户流程

### 8.1 总流程

```text
进入测字
  → 选择“了解一个字”或“一字观照”
  → 主动输入一个字，或在一字观照中随机取字
  → 校验字符与能力状态
  → 查看资料，或选择固定主题后生成观照
  → 可查看来源、切换已审核角度、转到另一条路径
  → 可预览并生成本地 PNG
  → 离开、刷新或重新开始后清除本次状态
```

进入页面不自动读取档案、不自动抽字、不自动生成、不自动保存。

### 8.2 两条路径互通

一字观照结果提供“了解这个字”入口。切换到资料路径时可以在当前页面会话中保留同一个字，但不能把主题、联想或历史案例写入资料事实。

从资料路径进入一字观照时必须重新检查该字的观照能力；只有基础资料并不表示可以生成娱乐内容。

## 9. 字符输入契约

### 9.1 基本规则

- 输入框只接受一个当前字库明确支持的汉字记录；
- 去除首尾空白后进行 Unicode 安全的单字符判断；
- 不以 JavaScript UTF-16 `length === 1` 作为唯一判断；
- 第一版不接受字符加变体选择符、组合序列、多个汉字、字母、数字、表情或标点；
- 页面显示实际采用的字形，不在后台静默替换。

### 9.2 简繁、异体与地区口径

- 简体、繁体和异体字分别建立记录；
- 可以展示已核验的对应关系，但不能自动把输入改成另一字形；
- 第一版以中国大陆现代规范汉字为主要使用场景；
- 其他地区或历史字形只有在口径、来源和权利状态清楚时展示；
- 未支持字提示用户更换或进入其他已有资料，不猜测笔画和结构。

### 9.3 未收录提示

推荐文案：

> 这个字暂未完成资料核验，当前不能生成结果。你可以更换一个字，或使用“随机取字”。

## 10. 主动输入与随机取字

### 10.1 主动输入

“心中已有一字”为默认方式。用户可以输入当下想到、看到或希望了解的汉字。产品不要求这个字具有神秘来源。

### 10.2 随机取字

“随机取一字”为一字观照的辅助方式：

- 只从 `observation = approved` 且不属于高风险的字库中等概率抽取；
- 使用浏览器安全随机能力；
- 安全随机失败时显式提示用户主动输入，不回退 `Math.random()`；
- 在可行范围内避免连续两次抽到同一个字；
- 不使用日期、账号、档案、设备或访问历史调整概率。

随机说明固定表达：

> 这个字由程序随机抽取，用于趣味联想，不代表命运安排或特殊征兆。

不得使用“天意赐字”“缘分之字”“今日注定之字”等文案。

## 11. 主题契约

第一版只允许六个固定主题：

```text
casual       随意看看
present      当下状态
learning     学习与成长
action       工作与行动
relations    人际相处
affection    感情思考
```

“随意看看”为默认选项。第一版不提供“其他”或自由文本主题。

主题只决定观照内容的阅读角度，不参与事实资料、历史案例、随机字概率或能力状态。不得提供健康、疾病、财务、投资、法律、诉讼、生死、考试结果、婚姻结果或复合概率等主题。

### 11.1 状态中立

全部主题内容必须满足：

- 不假设用户正在学校、就业、创业、求职或考试；
- 不假设用户单身、恋爱、已婚、分手或准备复合；
- 不假设用户存在朋友、同事、上司、伴侣或具体矛盾；
- 不诊断焦虑、抑郁、迷茫或其他心理状态；
- 不因为选择主题就把用户归入长期画像。

使用“如果你正在考虑”“在你关注的事情中”等条件表达，不使用“你最近工作不顺”“你的伴侣需要”等无输入断言。

## 12. 多音、多义与语义歧义

“了解一个字”可以展示一个字经过核验的多个常用读音和常用义，不强行选择一个。

第一版一字观照只收录语义边界清楚、能够稳定建立联想的字。多音、多义或使用场景容易改变核心含义的字，在没有设计“这次想到的是哪种意思”选择器前不得进入观照字库。

提示文案：

> 这个字有多个常用读音或含义，当前无法确定你想到的是哪一种。你可以先查看汉字资料，或换一个字进行一字观照。

系统不得默认选择所谓最常见含义。后续增加义项选择必须形成独立版本，不从本文自动推导。

## 13. 高风险汉字

疾病、死亡、灾难、自伤、犯罪、贫困、侮辱及其他可能被个人化为恐吓结论的汉字：

- 基础资料已核验时，可以在“了解一个字”中中性展示；
- 不进入一字观照；
- 不进入随机字库；
- 不产生强行正面化的“坏字转好运”内容；
- 不根据单字输入触发心理诊断或危机判断。

推荐提示：

> 这个字的资料可以正常查看，但它涉及较强的疾病、灾难或伤害含义，第一版暂不用于个人化文字联想。

高风险清单属于版本化内容治理资产。新增观照字时必须通过该清单和人工风险抽查。

## 14. “了解一个字”结果契约

结果按以下顺序展示：

1. **字头**：当前字形、全部已核验常用读音、规范状态和“资料已核验”标签；
2. **基本资料**：笔画、部首、结构和笔顺；
3. **常用含义**：普通用户可理解的常用义及对应来源；
4. **字形与历史**：有可靠材料并允许公开时才出现，区分古文字形、历史解释和现代含义；
5. **历史测字资料**：有案例时显示收录状态，用户主动展开；
6. **资料来源**：来源、版本、适用口径、核验和权利状态。

核心字段缺失或冲突时，不显示“资料已核验”。历史字形、笔顺动画和历史案例属于可选字段，缺少它们不使用默认值补齐。

本路径不得展示笔画五行、偏旁五行、结构性格、吉凶等级、事业感情或行动建议。

## 15. “一字观照”结果契约

### 15.1 结果顺序

1. **本次字与主题**：汉字、主题和持续可见的 `娱乐内容` 标签；
2. **从这个字出发**：一至两个经审核的编辑联想方向；
3. **本次观照**：简短、温和、非断言式的主题联想；
4. **留给自己的问题**：一个主要自我提问；
5. **换个角度**：按固定顺序切换，显示当前角度位置；
6. **进一步了解**：进入同一字的事实资料；
7. **内容边界与生成规则**：说明实际输入、没有读取的信息、选择方式和不能说明的内容。

### 15.2 内容表达

允许使用“可以联想到”“不妨思考”“如果你正在关注”等开放表达。

禁止使用：

- 大吉、吉、半吉、凶；
- 运势、佳兆、灾祸、转运、改运；
- 窥天机、命中注定、万事可期；
- 一定、必然、保证、将会发生；
- 对性格、事业、感情、学业、健康、财务和未来事件的判断；
- 以善恶、修身或所谓正能量否定用户现实感受的道德化结论。

### 15.3 示例

“明”在“学习与成长”主题中的候选形式：

> 项目编辑联想：看清、辨别、显现。
>
> 从“看清”这个角度出发，你目前最需要明确的，是目标、方法，还是下一步行动？

该示例不是正式内容记录，也不表示“明”已经通过资料、权利和内容审核。正式结果只能来自批准的数据包。

## 16. 娱乐性质披露

采用“持续可见但不反复打断”的方式：

- 模式卡显示 `娱乐互动`；
- 生成按钮上方显示短说明；
- 结果标题旁显示 `娱乐内容`；
- 结果底部显示完整边界和生成规则；
- 不为每次生成、换角度或导出重复弹窗；
- 不用“我已阅读并同意”复选框替代清晰说明。

短说明候选：

> 内容由已审核的文字联想规则生成，用于娱乐与自我观察，不是对现实情况或未来事件的判断。

完整说明候选：

> 本次内容属于文字联想与娱乐体验。系统未读取你的个人档案，也不了解你的完整经历；内容不构成心理分析，也不构成对感情、学业、职业、健康、财务或未来事件的预测与建议。

全站首次使用前的隐私政策同意机制继续由全局规范处理；本工具零持久化，不额外伪造一份“测字隐私同意”。

## 17. 内容生产与审核

### 17.1 内容单元

每个观照字至少维护：

- 已核验的事实记录引用；
- 二至四个项目编辑联想关键词；
- 六个固定主题的内容能力；
- 每个主题至少两个角度；
- 对应的一个自我提问；
- 内容版本、状态和风险标记。

事实资料、编辑联想、主题模板和历史材料必须存放在不同数据域，不能使用一个 `description` 字段混装。

### 17.2 轻量审核责任

- 事实资料通过来源数据导入、结构校验和异常报告完成批量检查；
- 编辑联想由少量逐字关键词和经审核的通用主题结构组成；
- 程序可以确定性组合已经批准的内容单元，但不能现场创造新的事实、结论或长篇解释；
- 历史案例逐条核验；
- Codex 负责来源、规则、高风险和验收审查；
- 实施代理负责按计划建设数据、检测和页面；
- 用户只需裁决产品规则、代表性样例和最终体验，不承担逐字审核。

### 17.3 自动检查不能替代内容判断

自动化负责缺字段、禁止词、状态、版本、来源引用和组合契约。代表性字、边界字、负面字和多义字仍需抽样阅读，不能因 schema 合法就宣称文案自然、准确或适合公开。

## 18. 历史案例契约

历史案例只属于资料层：

- 默认只显示“已收录相关历史案例”，由用户主动展开；
- 记录时代、人物、问事情境、原文、现代说明、出处和材料性质；
- 同一个字存在相互不同的历史解释时并列展示，不选出唯一答案；
- 文学作品、笔记传闻、方法书规则和可证史实分别标注；
- 不把小说或笔记故事宣传为真实发生；
- 不把历史解释应用到当前用户；
- 不参与观照关键词、主题内容、自我提问和随机概率；
- 疾病、死亡、灾难等高风险案例第一版不进入与用户输入关联的结果页。

一字观照最多提供普通链接：

> 这个字还收录了历史测字资料，可前往了解。

不得写成“古人以此字判断凶险，因此你也应注意”。

## 19. 来源体系

### 19.1 四级来源

1. **规范与技术数据**：规范字范围、编码、部首、笔画等；
2. **现代汉字学资料**：读音、部件、形义和字形演变；
3. **历史测字原始材料**：历史方法和案例；
4. **现代学术研究**：历史背景、方法变化和社会文化意义。

现代研究不能替代具体字的数据，历史材料存在也不能证明占卜具有现实预测能力。

### 19.2 来源状态与人工审核

```text
sourceStatus:
  verified_primary | verified_secondary | implementation_only
  disputed | unverified | no_source

sourceReviewStatus:
  unreviewed | in_review | approved | rejected
```

上述枚举逐字继承公共规范：`sourceStatus` 只回答证据支持程度，`sourceReviewStatus` 只回答人工核验流程。汉字资料和历史事实须有 `verified_primary / verified_secondary` 的直接支持并经 `sourceReviewStatus = approved`，同时通过权利和内容门禁，才能公开。项目创作的观照提示按其真实性质审核，不伪造古籍来源；`implementation_only` 只能支持项目规则，不能支持汉字学或预测性结论。

旧表中的 verified、pending、conflict、rejected、notApplicable 不再作为另一套来源枚举，也不能一对一自动升级：旧 verified 必须检查实际证据后区分 primary/secondary 和审核流程；pending 按实际核验进度记录；冲突记为 disputed；拒绝记在 sourceReviewStatus；不适用事项写入说明，不伪造已验证来源。引用链接存在或测试通过都不能补齐核验。

### 19.3 中国大陆现代规范为主

第一版以《通用规范汉字表》为规范范围主要依据。其他数据源使用具体地区和版本口径；不同口径可以并列，同一口径的未解决冲突记为 `sourceStatus = disputed`。只有冲突影响必需基础字段时，才把字的基础能力记为 `basicFacts = conflict`；可选历史字形或案例记录单独隔离，不连带关闭无关且已核验的基础资料。是否影响观照仍按语义、字形和内容依赖逐项判断。

核心字段存在未解决冲突时，该字不能成为 `basicFacts = verified`；存在语义或字形冲突时也不能进入一字观照。

## 20. 来源与权利双重门禁

每条资料分别记录：

```text
sourceStatus
sourceReviewStatus
rightsStatus
sourceTitle
sourceVersion
supportedFields
usageMode
locator
notes
```

`rightsStatus` 至少区分：允许项目使用、仅允许链接或核对、待确认、禁止使用。

规则：

- 权威资料不等于可以批量复制；
- 历史原典进入公版不等于现代整理、注释、翻译和数据库界面不受保护；
- 学术数据库授权不明确时只作核对入口或外部链接；
- 项目白话说明标记为项目说明，不复制网络文章冒充原创；
- 来源可信但权利不明确时不公开正文、图片或批量数据；
- 允许转载但来源无法支持结论时也不得作为事实依据；
- 字形图、笔顺动画、字体和数据文件分别检查许可证并保留许可文本。

公开字段必须同时通过 `sourceStatus`、`sourceReviewStatus`、`rightsStatus` 和对应内容审核；单独任一状态通过都不能解锁。

## 21. 确定性与随机性

- 相同产品契约版本、资料版本、观照内容版本、汉字、主题和角度必须得到相同内容；
- 默认显示固定第一角度；
- “换个角度”按固定顺序循环并显示如“角度 1/2”；
- 生成时间不参与内容选择；
- 日期、账号、档案和访问次数不参与内容选择；
- 随机只负责从批准字库取字；
- 不把切换角度描述成运势变化。

## 22. 页面状态与失败契约

页面使用公共 `ToolResultState`。以下名称仅用于领域步骤或操作反馈，不组成替代公共 phase 的总状态：

| 场景或领域反馈                | 公共状态映射与边界                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 尚未操作、填写、输入满足门槛  | `phase = idle / editing / ready`                                                                                         |
| 真正异步加载或生成            | `phase = processing`；即时本地查询不制造加载                                                                             |
| invalidInput                  | `phase = failure`、`failureCategory = invalid_input`，详细原因定位到输入                                                 |
| factsUnavailable              | 当前请求没有可展示资料时为 `failure / unsupported_input`；不估算缺失资料                                                 |
| factsReady / observationReady | 当前请求形成可展示结果时为 `success / unique`；能力是否开放仍按第 7 章判断                                               |
| observationUnavailable        | 已有基础资料时保留基础结果，将观照不可用作为能力说明；若本次请求的是不可用观照，明确该操作失败，不把基础结果冒充观照结果 |
| contentError                  | 当前请求依赖的内容损坏则 `failure / engine_error`，详细代码说明内容原因；可独立保留的基础资料不因此被篡改                |
| randomError                   | 取字操作失败，保留已生成结果，不伪造随机字；无结果时说明可手动输入                                                       |
| exportError                   | 仅导出操作失败，不把有效结果改成计算失败                                                                                 |
| 输入、主题改变后仍持有旧结果  | `freshness = stale`；禁止导出，用户主动重新生成                                                                          |

第一版不以 `partial` 表示附加资料缺失；能力分层、随机操作和导出状态与公共计算状态分开。领域详细原因使用 `failureDetailCode`，不添加公共失败类别。已有结果与本次操作失败并存时，标清各自归属，不展示为本次成功。

处理规则：

- 输入不合法时指出字符要求；
- 汉字未收录时不估算；
- 只有基础资料时引导查看资料，不伪造观照；
- 缺少某主题内容时禁用该主题，不借用其他主题；
- 版本、来源引用或必填字段异常时停止展示；
- 随机失败时引导主动输入；
- 修改汉字或主题后旧结果进入 `stale` 并禁止导出；
- 导出失败保留当前结果和用户操作路径。

不得只显示“出错了”，也不得捕获错误后返回默认吉凶、默认结构或通用解释。

## 23. 处理反馈与动画

本地查询能够立即完成时直接显示结果，不设置假的 300 毫秒或其他人为计算延迟，不显示“正在感应”“正在推演”等文案。

可以保留短暂的水墨过渡作为视觉反馈，但必须：

- 与数据处理状态分开；
- 不阻止用户继续操作；
- 不掩盖错误；
- 遵循 `prefers-reduced-motion`；
- 不声称动画代表复杂计算或神秘过程。

## 24. 隐私、账户、历史与日志

第一版采用最低数据模式：

- 游客与登录用户能力一致；
- 不强制登录；
- 不读取本人档案或关系状态；
- 不向服务器发送汉字、主题和结果；
- 不把汉字、主题、角度和结果放入 URL、查询参数或路由状态；
- 不按用户输入的汉字或主题发起远端数据请求；需要的公开内容包按固定版本加载，不能让请求地址泄漏本次输入；
- 不调用 `/api/divinations` 或其他保存接口；
- 不写入 `localStorage`、`sessionStorage`、IndexedDB 或 Service Worker 持久缓存；
- 不把输入、主题和结果发送给第三方统计、错误追踪或分析服务；
- 普通日志和错误日志不记录输入和结果正文；
- 离开、刷新或关闭页面后清除当前字、主题、角度和结果；
- 不进入最近使用、个人推荐和探索轨迹。

输入和内容统一按文本渲染，不允许把汉字、来源文本、编辑联想或历史原文直接交给未经清理的 `v-html`。外部来源链接只允许批准的 `https` 地址，并使用适当的跨站安全属性。

未来增加主动收藏、跨设备历史或 AI 分析时，必须重新讨论用途、单独同意、删除、导出和版本行为。

## 25. 旧历史与数据库重建

现有测字历史不迁移为新资料或一字观照记录：

- 新页面不得读取和恢复旧吉凶结果；
- 不把旧记录重新标记为娱乐内容后继续展示；
- 不为旧结果补造来源、规则或版本；
- 在已批准的一次性数据库重建前，旧记录只属于不兼容的遗留数据；
- 本文不授权立即删除数据；
- 真正执行数据库重建前仍需用户明确确认。

该规则继承 [用户档案与数据生命周期规范](profile-and-data-lifecycle-spec.md) 已批准的“旧数据库不迁移”决定。

## 26. 版本与结果数据契约

### 26.1 版本字段

每次资料或观照结果至少携带：

```text
contractVersion
characterDataVersion
observationContentVersion
sourceRegistryVersion
characterId
mode
themeId
angleId
generatedAt
```

历史案例另带原典版本、卷次／页码／条目、录入版本、项目说明版本和核验状态。

`generatedAt` 只表示浏览器本地生成时间，不是占卜时间，也不参与内容选择。

### 26.2 版本行为

- 页面、自动化测试和导出读取同一份记录；
- 数据版本不匹配时显式失败，不跨版本拼接；
- 修正资料、联想关键词、主题结构或案例说明时升级对应版本；
- 用户可见页面只显示简短版本，展开后查看完整来源和版本；
- 本地导出保留生成时版本标记。

## 27. 模块化架构

候选在 Nuxt 3 模块化单体中至少分为：

1. **汉字资料领域**：字符校验、能力状态、事实和冲突；
2. **一字观照领域**：固定主题、内容单元、确定性角度和随机字池；
3. **历史案例领域**：原典记录、材料性质、现代说明和风险；
4. **来源与能力目录**：来源、权利、版本和每字能力；
5. **页面与导出层**：模式、输入、状态、阅读和本地 PNG。

```text
输入汉字
  → 字符校验与能力查询
  → 汉字事实记录
      ├─ 了解一个字 → 资料／来源／可选历史案例
      └─ 一字观照   → 固定主题／已审核内容／自我提问
  → 页面展示或本地 PNG
```

页面不维护算法和长篇内容；导出不复制结果逻辑；历史案例不进入观照领域；观照领域不接触档案和服务器历史。

## 28. UI 与信息架构

### 28.1 视觉边界

保留现有墨韵设计语言和适合复用的卡片资产，但信息结构以本文为准。删除吉凶徽章、五行颜色、命运判词和“测字笺”中暗示个人占卜的内容。

模式选择使用两张完整卡片。进入某模式后显示明确返回和切换路径，不把两套结果混排在一张长页面中。

### 28.2 来源正常进入阅读流

不恢复悬浮“注”、固定宽度气泡、覆盖正文的来源面板或只能悬停查看的提示。来源、历史案例、生成方式和限制采用普通正文、状态标签与可键盘展开区域。

### 28.3 不只靠颜色

资料状态、娱乐性质、不可用、冲突、过期和失败均使用文字和语义状态，不通过红绿、吉凶色或印章颜色单独表达。

## 29. 导出与分享

第一版只允许浏览器本地生成 PNG：

- 导出前提供准确预览；
- 图片不上传服务器；
- 导出失败不改变页面结果；
- 不包含昵称、账号、档案、设备或无关信息；
- 不提供公开链接、二维码、社交平台直传、PDF、Word、JSON 或批量导出。

### 29.1 资料导出

包含当前字、读音、基本资料、当前展示的常用义、来源名称和资料版本。不自动包含折叠的历史测字案例，不导出待核验字段。

### 29.2 一字观照导出

包含当前字、主动选择的主题、`娱乐内容` 标签、当前角度的联想、自我提问、内容版本和简短边界说明。不导出其他未显示角度。

输入或主题改变后旧结果过期并禁止导出，重新生成后才可预览新图片。图片可以使用“玄·道”品牌，但不得加入“灵验”“天机已定”等宣传语。

## 30. 移动端与可访问性

- 320、360、390、414 CSS 像素宽度均能完成两条路径；
- 页面无横向自由滑动、文字重叠、遮挡和内容裁剪；
- 两张模式卡、主题、生成、换角度、展开来源和导出具有足够触控区域；
- 六个主题在窄屏自然换行，不缩成不可用小标签；
- 大字展示不挤压读音、状态和来源；
- 内容采用单列、正常流卡片，不依赖固定最小宽度；
- 200% 文字缩放与 400% 页面回流下完整可用；
- 500% 作为压力测试，核心内容和操作仍可访问；
- 不禁用浏览器缩放，不用全局隐藏溢出掩盖问题；
- 键盘可以选择模式、输入、主题、角度、来源和导出；
- 错误与字段具有关联语义，状态变化可被辅助技术感知；
- 动画支持减少动态效果。

验收顺序为自动化、Codex 内置浏览器桌面与移动模拟、用户真实手机手动确认。任一层失败都不能宣称移动端完成。

## 31. 自动化与验收契约

### 31.1 输入与字库

- 单字符和 Unicode 边界测试；
- 多字符、字母、数字、标点、组合序列和未收录字失败；
- 简繁、异体不静默转换；
- 生产代码不存在 Unicode 码位估算笔画；
- 每个能力状态满足对应 schema。

### 31.2 事实与来源

- 每个公开字段链接已核验来源和允许的使用方式；
- 未通过第 19、20 章来源、人工审核和权利门禁的记录不进入公开结果；能力层 pending/conflict 不得伪装为已开放；
- 核心字段缺失时不显示“资料已核验”；
- 页面、导出和测试读取同一记录。

### 31.3 一字观照

- 只接受六个固定主题；
- 同版本、字、主题和角度得到相同内容；
- 角度按固定顺序循环；
- 主题缺失不使用默认模板；
- 随机字池只含批准字，安全随机失败无 `Math.random()` 兜底；
- 30 个首轮字、六主题、每主题至少两个角度的完整性检查通过。

### 31.4 内容治理

公开页面、结果对象和默认导出中不得出现：

- 旧吉凶等级和 81 数理；
- 笔画五行和偏旁五行；
- 性格、事业、感情、学业、健康、财务和未来预测；
- 命定、保证、转运、灾祸和窥天机；
- 未输入的伴侣、婚姻、工作、考试和心理状态假设；
- 把项目编辑内容标为古籍；
- 把文学或笔记记载标为历史事实。

禁止词扫描只是最低检查，不能替代上下文抽样阅读。

### 31.5 隐私、网络和旧历史

- 游客完整可用，不跳转登录；
- 不读取档案；
- 生成、换角度和导出不调用保存接口；
- 不产生长期浏览器存储；
- URL、查询参数、路由状态和按输入发起的网络请求不包含汉字、主题、角度或结果；
- 输入、主题和结果不进入日志或第三方请求；
- 用户输入、来源文本和历史原文按文本安全渲染，不存在未经清理的 HTML 注入；
- 刷新或离开后状态清除；
- 旧测字历史不能被新页面恢复。

### 31.6 页面、导出和工程

- 两种模式、全部失败、过期、来源展开和导出预览具有组件测试；
- 导出预览与 PNG 内容一致；
- 移动端与缩放要求通过；
- `npm run typecheck`、`npm run test`、`npm run lint`、`npm run build` 通过；
- 中文编码检测和 `git diff --check` 无异常；
- Codex 使用内置浏览器核验网络、存储、交互、响应式、禁止内容和导出；
- 用户完成真机手动验收。

自动化通过只说明实现符合契约，不能替代来源和权利账本。

## 32. 分能力重新开放门禁

### 32.1 “了解一个字”

只有同时满足以下条件才能讨论公开：

1. 规范字范围、读音、笔画、部首、结构和基本释义的来源及使用权限通过；
2. 公开字库的核心字段完整，冲突数为零；
3. 简繁、异体、多音、多义和未支持状态显式；
4. 来源、失败、隐私、导出、移动端和可访问性验收通过；
5. 旧预测字段不会从页面、SEO、历史和导出泄漏。

### 32.2 “一字观照”

只有同时满足以下条件才能讨论公开：

1. 至少 30 个 `observation = approved` 字；
2. 每个字覆盖六主题，每主题至少两个角度；
3. 多音多义、高风险和冲突字不在观照与随机池；
4. 编辑联想、主题结构、自我提问和边界说明完成内容审核；
5. 确定性、随机、状态中立、禁止内容和版本测试通过；
6. 游客、零档案、零持久化、本地导出和移动体验通过。

不足 30 个字时，“了解一个字”可以独立公开，一字观照显示“内容整理中”，随机取字保持禁用。

### 32.3 历史案例

历史案例逐条通过、逐条出现，不设虚假数量指标。每条必须完成原典、版本、定位、材料性质、现代说明、来源和权利审核。未通过的案例不影响前两类能力。

### 32.4 最终批准

每项能力通过技术门禁后只获得有限公开预览候选资格。恢复首页、目录、SEO、旧路由计算和导出前，仍需 Codex 依据证据审查，并由用户明确批准。

## 33. 推荐迭代顺序

后续实施必须拆成多个可独立验收的小阶段：

1. 旧测字页面、SEO、计算、保存、历史和导出的统一围栏；
2. 来源目录、权利状态、字库 schema 和冲突报告；
3. “了解一个字”的最小事实数据管线与代表字验证；
4. 双轨入口、字符校验和失败状态；
5. 一字观照内容模型、六主题、确定性角度与首批字；
6. 浏览器安全随机和随机字池；
7. 历史案例独立资料域与首批逐条核验；
8. 两套结果、来源正常阅读流和娱乐性质披露；
9. 本地 PNG 预览与导出；
10. 旧算法、旧常量、旧自动保存和过时测试退出；
11. 自动化、Codex 内置浏览器、用户真机和公开环境验收。

每个阶段开始前根据届时代码和正式规范形成独立计划。本文不是实施计划，也不授权当前立即执行。

## 34. 第一版非目标

- 笔画五行、偏旁五行、81 数理和吉凶判词；
- 性格、事业、感情、学业、健康、财务或未来预测；
- 把历史案例应用到当前用户；
- 自动添笔、减笔、拆分、合字、谐音和情境断事引擎；
- AI 解读和用户自带 API Key；
- 完整问题、个人故事和自由主题输入；
- 拍照识字、手写识别和书法评价；
- 第一版覆盖全部 8105 个规范汉字；
- 用户投稿、评论、社区和公开案例库；
- 收藏、云端历史、跨设备同步和个人画像；
- 档案、日期或访问行为驱动的推荐；
- 今日幸运字、命定之字和伪个性化；
- 公开分享链接、二维码、社交平台直传；
- PDF、Word、JSON 和批量导出；
- 独立 Spring Boot 后端、微服务或单独 AI 服务。

未来实现更接近历史测字的方法时，必须先选定具体底本、建立逐条规则证据、区分历史方法与项目实现，并重新讨论输入、娱乐边界、版本和风险。当前旧字形猜测不得直接升级为“传统测字算法”。
