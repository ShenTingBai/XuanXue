### 1.1 纯日期处理约束

- 公历输入日期一律以 `YYYY-MM-DD` 纯日期字符串表达，不做 UTC `Date` 中间转换，避免系统时区改变日历日期（治理规范 §8.1）。
- 年界判定以「公历日期 < 该公历年对应的农历正月初一公历日期」为「上一农历年」；等于或晚于正月初一为「当年」。

## 3. 失败分类映射

黄金样例 `expectedPhase` 对应领域输出 `phase`，只取 `success` / `failure`。成功用 `successQualifier: unique`；失败类别独立放 `failureCategory`，不得把 `invalid_input` 当作阶段。样例文件是预期数据，恢复成功预期不表示测试已运行。

| 情形                    | phase   | failureCategory   | failureDetailCode | 页面行为                                  |
| ----------------------- | ------- | ----------------- | ----------------- | ----------------------------------------- |
| 日期缺失/格式非法       | failure | invalid_input     | —                 | 指向具体字段，不调用引擎                  |
| 日期真实但 < 1901-01-01 | failure | unsupported_input | UNSUPPORTED_DATE  | 说明支持范围（1901-01-01 起），不近似计算 |
| 日期真实但 > asOfDate   | failure | unsupported_input | UNSUPPORTED_DATE  | 说明「不能查询未来/当日之后」，不近似计算 |
| 公历-农历换算异常       | failure | engine_error      | —                 | 说明未能生成，允许重试，不返回替代结果    |
| 公历年份越界却取模兜底  | 禁止    | —                 | —                 | 契约 §8.3 明确禁止 `公历年 mod 12` 后备   |

### 3.1 黄金数据的使用边界

- `golden_cases`：26个日期预期，18个成功预期逐例给齐传统分类四字段、`ruleVersion` 与 `yearBoundary.timezone`；日期与年界保留各自独立资料引用。
- `classification_cases`：60条以 `inputGanZhi` 为输入的纯分类预期；`cycleIndex` 从0起，显式列出天干、地支、生肖、年干阴阳五行、年支五行和纳音。来源是台账中的规则和逐对表，不是项目引擎输出。
- 两类共86条预期，不能合称86个日期换算样例；60条分类覆盖也不代替全部支持年份的春节前/当/后边界验证。
- `field_source_refs` 给出共享字段来源；逐例 `sourceRefs` 与年界来源仍保留。版本、时区是契约预期，传统分类不用于断言个人整体五行强弱。
- 后续代码验收另覆盖引擎失败注入、纯日期跨时区和完整支持范围；这些是运行行为，不能靠新增静态数据声称通过。

## 5. 农历年起止日期的实现约束（工程事实，只读源码审查）

- 只读审查 `node_modules/lunar-javascript/lunar.js`（LunarYear 类）确认：`LunarYear.fromYear(公历年)` 的
  `months` 数组**包含跨农历年的月份**，`getMonthsInYear()`/`getDayCount()` 均用 `m.getYear() === this._p.year`
  按**农历年号**过滤——即不能直接取 `months` 数组首尾作为某个农历年的边界，必须先按目标农历年号过滤。
  （v1 所述「按公历自然年聚合」为未经支持的概括，已删除；准确事实是「months 数组未按农历年过滤，
  需按农历年号 `getYear()` 筛选」。）
- 正确做法：农历年 `Y` 的公历起止 = `[正月初一(公历), 次年正月初一(公历) - 1天]`。
  正月初一公历日期按契约「正月初一」年界原则取得（已核验春节日期表，或由公历-农历换算反查正月初一）。
- 该约束为工程实现约束，黄金样例年界预期以 HKO 与 SRC-008 独立记录为准（计划 must_not：不运行 API 探测，
  本约束仅基于只读源码审查）。
