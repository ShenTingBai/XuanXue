>

> 最后更新：2026-09-06

> 适用范围：XuanXue 现有“姓名测试”退役、后续“姓名笔画与五格对照”候选的来源整理、领域实现、页面展示、导出、测试与重新开放验收

## 1. 文档目的

本文固定 XuanXue 现有“姓名测试”的退役决定，以及后续“姓名笔画与五格对照”候选工具的产品、内容、数据和工程边界。

本文不是对现有代码的背书，也不表示候选功能已经完成来源核验、代码实施或公开验收。后续来源账本、领域模块、页面、测试和实施计划不得绕过本文另行创造姓名判断规则。

本文中的“第一候选”指本轮讨论批准的最小候选能力，不表示它属于 XuanXue 首个核心治理版本。该能力优先级低于已经批准的核心基础与主要工具；来源或字库工作量不合理时，可以继续封存。

## 2. 核心裁决摘要

1. 现有“姓名测试”退役，不再以评分、吉凶总结、人格判断、改名建议或人生预测的形式公开。
2. 后续候选名称固定为“姓名笔画与五格对照”。
3. 候选明确属于近现代日本熊崎式姓名判断方法的资料对照，不包装成中国古代姓名学或科学测评。
4. 第一候选只处理姓名文字、历史字形、笔画、五格算式和逐格历史记录。
5. 不展示 0—100 分、总体等级、综合吉凶、三才吉凶、性格判断、健康婚姻财富事业预测或改名建议。
6. “人格”只作为五格体系术语，不等于心理学人格，也不表示项目对用户性格作出判断。
7. 用户可以输入示例名、笔名或任意测试文字；项目不要求、不推荐用户填写真实姓名。
8. 全程游客可用，不登录、不读取本人档案、不保存服务器历史、不长期写入浏览器存储。
9. 输入分为“姓氏部分”和“名字部分”，第一候选只支持姓一至二字、名一至二字。
10. 用户输入简体或繁体字后，必须看到并确认实际采用的历史字形与笔画；程序不得静默转换。
11. 一字对应多个历史字形时由用户选择；未核验字、无法显示字形或来源冲突时停止计算。
12. 现有 Unicode 编码估算笔画的兜底规则退出生产目标。
13. 五格只采用完成来源核验的一套熊崎式规则，不在第一候选中提供多流派切换。
14. 81 数理只做逐格历史资料对照，不把历史记录转化为针对用户的整体评判。
15. 超过 81 的结构数不自动循环；只有选定原始版本明确支持某种约减规则时才能另行讨论。
16. 高风险历史措辞采用中性主结果、来源核验后的折叠历史记录和时代局限说明，不做个性化恐吓。
17. 第一候选采用《通用规范汉字表》一级 3500 字作为首批覆盖目标；三级人名用字为下一扩展批次，二级字按后续需求扩展。
18. 导出只允许浏览器本地生成 PNG，默认匿名；用户主动选择包含输入文字时必须再次确认。
19. 候选采用 Nuxt 3 模块化单体中的独立姓名领域，不新建 Spring Boot 后端、不拆微服务、不接入 AI。
20. 当前目标状态为 `reviewStatus = in_review`、`exposure = internal`、`computePolicy = blocked`、`historyPolicy = disabled`；全部重新开放门禁通过后也只获得有限公开预览候选资格。

## 3. 产品定位与名称

### 3.1 对外名称

候选对外名称为：

> 姓名笔画与五格对照

不得恢复以下名称或同义营销表达：

- 姓名测试；
- 姓名打分；
- 姓名吉凶；
- 姓名运势；
- 姓名性格分析；
- 姓名改运；
- 一生姓名解析。

### 3.2 用户价值

该候选帮助用户理解：

- 一套近现代姓名判断方法怎样处理姓与名的边界；
- 输入文字在选定版本中采用什么历史字形和笔画；
- 天格、人格、地格、总格和外格怎样计算；
- 该历史版本怎样记录相应数理；
- 这些历史记录存在哪些证据边界、版本差异和时代局限。

该候选不帮助用户决定：

- 是否改名；
- 名字是否“好”或“坏”；
- 用户是什么性格；
- 用户是否会成功、富有、健康、结婚或长寿；
- 某个名字是否比另一个名字更适合现实人生。

### 3.3 与产品总纲的关系

该能力属于传统文化互动学习与规则透明展示，不是 XuanXue 的核心个人预测能力。它可以丰富项目对“传统规则怎样被数字化、核验和限制”的展示价值，但不能以功能数量为理由获得公开资格。

- SEO 元信息、站点地图和结构化数据；

只隐藏入口但保留直接路由计算不算完成。

## 5. 方法性质与可信度边界

### 5.1 历史性质

熊崎式笔画姓名判断是近现代日本形成并传播的姓名判断方法。项目必须明确说明这一历史背景，不得使用“中国古代流传”“源自《易经》的科学规律”或“千年姓名学”等无法由证据支持的表达。

### 5.2 证据能支持什么

原始著作、馆藏目录和学术研究最多能够支持：

- 某种方法在特定作品和时代中确实存在；
- 某个版本怎样定义字形、笔画、五格和数理；
- 后续研究怎样评价其历史来源、理论混合和可信度。

这些材料不能证明姓名笔画能够预测现实人格、健康、婚姻、事业、财富、寿命或人生结果。

### 5.3 页面固定边界文案

公开候选至少表达以下意思：

> 本页展示一种近现代姓名判断方法的文字、笔画和五格计算记录，帮助理解其规则与历史语境。它不是心理测评，也不能证明姓名会决定现实人生。

具体措辞可以根据 UI 空间进行等义精简，但不得删除“近现代方法”“规则资料”和“不代表现实判断”三层语义。

## 6. 使用者、输入对象与隐私

### 6.1 不要求真实姓名

页面字段统一称为：

- 姓氏部分；
- 名字部分；
- 要对照的姓名文字。

页面应主动说明用户可以输入示例名、笔名或任意测试文字。不得使用“请输入您的真实姓名”“真实姓名结果更准确”或类似诱导。

### 6.2 不读取本人档案

第一候选：

- 不读取本人档案；
- 不设置“使用已保存姓名”；
- 不新增真实姓名档案字段；
- 不询问输入属于本人还是他人；
- 不把输入写回本人档案。

### 6.3 不保存他人或本人姓名

无论用户输入本人、他人、笔名还是示例文字，系统都按一次性当次草稿处理。关闭或刷新页面后清空；不产生服务器历史或跨设备记录。

## 7. 输入结构范围

### 7.1 第一候选支持组合

第一候选的产品目标只包含：

| 姓氏部分 | 名字部分 | 结构     |
| -------- | -------- | -------- |
| 一字     | 一字     | 单姓单名 |
| 一字     | 二字     | 单姓双名 |
| 二字     | 一字     | 复姓单名 |
| 二字     | 二字     | 复姓双名 |

最终开放仍以选定原始版本是否存在足够公式证据为准。若其中某种组合无法完成核验，应继续缩小支持范围，而不是按工程直觉补公式。

### 7.2 不支持不等于姓名错误

三字姓、三字以上名字、少数民族姓名、音译姓名或其他复杂结构不进入第一候选。页面只能说明当前版本尚未完成相应规则核验，不得评价输入“不是正常姓名”“姓名不合法”或“无法测算”。

### 7.3 不继承旧长度

现有姓最多四字、名最多八字的界面上限没有来源依据，不进入新候选。

## 8. 文本识别与字符校验

### 8.1 允许内容

第一候选只接受已进入首批字形账本的汉字。数字、拉丁字母、Emoji、标点、控制字符和内部空格不参与计算。

输入框首尾意外空格可以在进入字形检查前清理，但页面不得修改汉字本身。

### 8.2 Unicode 边界

领域实现必须按完整 Unicode 字符或字素处理汉字，不得使用会把扩展区字符拆成两个 UTF-16 代码单元的长度和切分逻辑。

至少区分：

- 输入字符；
- Unicode 代码点；
- 展示字形；
- 采用的历史字形；
- 变体映射；
- 笔画记录。

### 8.3 无法显示的字形

如果目标浏览器、字体或导出环境无法可靠显示候选历史字形，该字符视为暂不支持。不得以空框、替代字符、相近字或图片猜测继续计算。

## 9. 首批字库覆盖

### 9.1 覆盖基线

第一候选以 2013 年《通用规范汉字表》一级字表 3500 字作为首批覆盖目标。该字表只定义候选输入范围，不承担熊崎式历史笔画来源职责。

### 9.2 后续扩展顺序

首批完成后：

1. 优先评估三级字表中的姓氏、人名相关用字；
2. 再根据实际需求扩展二级字；
3. 复杂姓名结构与新增字符覆盖分别治理，不能因为补字而自动扩大五格公式范围。

### 9.3 覆盖报告

每次字形账本构建至少生成：

- 目标字符总数；
- 已核验并可计算数；
- 存在多个候选历史字形数；
- 来源冲突数；
- 无法显示数；
- 缺少来源数；
- 相对上一版本的新增、修订、撤回记录。

首批开放门槛必须可以机械判断：3500 个目标字符中的每一个，都必须具有已批准的唯一历史字形与笔画，或者具有可由用户明确选择的多个已批准候选。首批清单中的未审核、来源缺失、冲突未决和无法可靠显示数量必须全部为零；否则工具继续隐藏。

## 10. 历史字形与笔画账本

### 10.1 单字记录

每个可计算字符至少记录：

- `characterId`；
- 用户可输入字形；
- Unicode 代码点；
- 采用的历史字形；
- 历史字形笔画数；
- 简体、繁体、异体关系；
- 来源作品、版本和稳定位置；
- 来源状态与人工审核状态；
- 是否存在候选歧义；
- 是否可在支持环境可靠显示；
- 数据版本和修订记录。

### 10.2 简繁与异体处理

- 不静默进行简繁转换；
- 输入字形与采用字形必须同时显示；
- 一对一映射仍须由用户确认；
- 一对多映射必须让用户选择具体历史字形；
- 不能由常用程度、用户地区或程序默认值代替选择；
- 无法确认时停止整个计算。

例如一个简化字可能对应多个传统字形时，界面应展示每个候选字形、笔画和来源，而不是只给出一个“系统推荐”。

### 10.3 禁止兜底

以下方式不得成为正式笔画：

- Unicode 编码取模；
- 字符序号估算；
- 相近字代替；
- 缺失时随机笔画；
- 把现代字体笔顺数据直接称为康熙笔画；
- 未记录版本的网络字典结果。

## 11. 字形数据来源边界

### 11.1 正式来源

正式历史笔画必须回链到选定熊崎式底本明确采用的字形依据，以及经批准的历史字形资料。不能仅因为资料名称包含“康熙”就视为已经证明计算口径。

### 11.2 工程辅助资料

下列资料可以作为录入、识别或交叉检查种子，但不能单独取得正式笔画权威地位：

- Unicode Unihan；
- Make Me a Hanzi；
- 现代字体轮廓；
- 《通用规范汉字表》与现代笔顺规范；
- 现有 `constants/stroke-dict.ts`。

如采用开源数据，必须固定仓库版本、许可证和导入过程。

## 12. 底本与来源策略

### 12.1 原始资料优先顺序

第一候选采用以下审计顺序：

1. 优先审计 1931 年《熊崎式姓名学大奥義》中可以合法公开核验的卷次；
2. 使用 1929 年《姓名の神秘》核对方法源流与早期表述；
3. 使用 1933 年《熊崎式姓名学》交叉核对公式、字形和数理差异；
4. 使用现代学术研究说明历史流变、争议和可信度边界。

### 12.2 当前旧引用的处置

现有代码声明熊崎健翁《姓名学の極意》（1934）奠定全部规则，但当前没有完成可靠书目和页码核验。该说法保持 `unverified`，不得进入公开页面或正式规则说明。

没有找到并不等于证明作品不存在；后续若获得可靠书目和原书，应作为新证据进入审核，而不是倒写当前状态。

### 12.3 单一版本

第一候选只采用一套明确版本的五格与数理规则。其他版本只用于差异说明，不提供用户切换，也不把多个版本拼成“综合姓名学”。

## 13. 来源账本

每条来源至少记录：

- `sourceId`；
- 作品名称与原文书名；
- 作者或责任机构；
- 出版年代、出版机构和具体版本；
- 卷、章、页或稳定定位；
- 原文语言；
- 必要短摘；
- 项目中文释义；
- 版权或许可证状态；
- 稳定链接与访问日期；
- `sourceStatus`；
- `sourceReviewStatus`；
- 支持的 `ruleId`、`characterId` 或 `numberRecordId`；
- 异文、争议和撤回记录。

“同上”“网上资料”“民间说法”“多个网站综合”不能成为正式来源。

## 14. 五格公式

### 14.1 符号

设：

- 姓氏部分笔画序列为 `S = [s1, ..., sm]`；
- 名字部分笔画序列为 `G = [g1, ..., gn]`；
- 第一候选中 `m`、`n` 只能为 1 或 2；
- `V(x)` 表示当长度为 1 时使用虚数 1，否则为 0。

### 14.2 计算定义

在完成原始版本核验后，第一候选目标公式为：

```text
天格 = sum(S) + V(m)
人格 = last(S) + first(G)
地格 = sum(G) + V(n)
总格 = sum(S) + sum(G)
外格 = 总格 - 人格 + V(m) + V(n)
```

### 14.3 虚数 1

- 单姓时天格加入虚数 1；
- 单名时地格加入虚数 1；
- 总格只计算实际文字，不计虚数；
- 外格包含适用的外部实际文字和虚数位置；
- 每个虚数 1 必须在页面算式中明确显示。

### 14.4 外格纠错

现有实现统一使用“总格－人格＋1”，不能正确表达单姓单名与其他结构的虚数差异。新候选不得继承该简化。

### 14.5 透明算式

每一格必须同时展示：

- 参与字符；
- 输入字形与采用历史字形；
- 每字笔画；
- 适用的虚数 1；
- 完整加减过程；
- 最终结构数；
- 公式版本与来源记录。

## 15. 81 数理记录

### 15.1 逐格查表

每个五格结果只查询对应数理记录。第一候选不把五格再次合成总分或综合等级。

单格记录可以包含：

- 格名与结构数；
- 该版本的历史分类；
- 该版本的条目名称；
- 项目中性释义；
- 来源和版本；
- 经核验且允许引用的历史原文；
- 内容性质与局限说明。

### 15.2 历史分类的表达

允许表达：

> 该版本将 15 数记录为“吉”。

不得表达：

> 你的人格是大吉，所以事业一定成功。

“吉、凶、半吉”等只属于历史资料中的分类字段，不能成为页面标题、醒目印章、行动建议或现实预警。

### 15.3 超出 81

结构数大于 81 时：

- 不自动取模；
- 不循环回 1—81；
- 不默认取尾数；
- 仍可显示完成核验的五格结构数；

## 19. 三步使用流程

### 19.1 第一步：输入文字

用户输入姓氏部分和名字部分，页面进行结构和字符校验。点击“检查字形与笔画”后进入字形核验，不立即计算五格。

### 19.2 第二步：确认字形与笔画

逐字展示：

- 输入字；
- 候选历史字形；
- 笔画；
- 来源状态；
- 是否存在版本或映射歧义。

所有字符都有唯一已核验字形，或用户已解决全部一对多选择后，才能点击“生成五格对照”。

### 19.3 第三步：查看结果

结果包含确认快照、五格解释、完整算式、逐格历史记录、来源索引和导出入口。

点击“重新对照”后携带当前文字返回第一步。进入修改状态后旧结果不能继续导出，避免新草稿和旧结果混用。

### 19.4 不制造加载

本地检查和计算能够即时完成时，不显示人为延时或虚假加载动画。只有真实异步过程才进入加载状态，并允许失败后保留输入重试。

## 20. 页面状态合同

复用公共 `ToolResultState`；字形检查和用户选择保留为领域步骤，不再定义一套并列总状态：

| 场景或领域步骤                                    | 公共状态映射                                                                    | 允许操作                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 尚未开始／正在输入                                | `phase = idle / editing`                                                        | 输入、查看方法边界                                           |
| `checking`：真实字形检查                          | `phase = processing`                                                            | 等待；取消能力须由实施验证，不作虚假承诺                     |
| `needs_choice`：存在一字多形                      | `phase = editing`，不是已生成候选结果                                           | 选择候选、返回修改                                           |
| 必填部分为空                                      | `phase = failure`、`failureCategory = missing_required_input`                   | 指出需要填写的部分，保留其他输入                             |
| 格式或字符不符合输入要求                          | `phase = failure`、`failureCategory = invalid_input`                            | 定位格式问题，不评价姓名本身                                 |
| `unsupported`：结构、字形、来源或显示超出支持范围 | `phase = failure`、`failureCategory = unsupported_input`                        | 说明当前版本未支持，不使用默认笔画，不把三字姓等称为非法姓名 |
| 全部字形已确认                                    | `phase = ready`                                                                 | 生成五格对照、返回修改                                       |
| `calculating`：真实计算                           | `phase = processing`                                                            | 等待真实结果，不人为延迟                                     |
| 结果完整且版本有效                                | `phase = success`、`successQualifier = unique`、`freshness = current`           | 阅读、展开证据、预览导出                                     |
| 计算或必需内容查询异常                            | `phase = failure`、`failureCategory = engine_error`，细节用 `failureDetailCode` | 保留输入重试，不展示部分伪结果                               |
| 输入、字形、规则或来源版本改变                    | 仍持有旧结果时 `freshness = stale`，不是新的 phase                              | 禁止导出，重新确认和计算                                     |

第一候选不生成未确认字形的部分或候选五格。缺少可选历史记录时仍按既定边界展示结构数和过程，不把附加内容缺失伪装成另一个总状态。导出失败单独记录，不破坏当前有效结果。

错误必须定位到具体字符、步骤和原因。不能用“计算失败，请检查输入”覆盖未支持字符、来源冲突、内容缺失和内部异常。

## 21. 结果信息架构

结果按以下五层顺序组织：

### 21.1 本次对照对象

展示姓氏部分、名字部分、输入字形、采用历史字形、笔画和版本。这里是用户确认过的不可变结果快照，不与正在编辑的新草稿共享。

### 21.2 五格是什么

使用普通语言说明五个格只是该历史方法中的结构名：

- 天格：姓氏部分形成的结构数；
- 人格：姓氏末字与名字首字形成的结构数；
- 地格：名字部分形成的结构数；
- 总格：全部实际文字笔画总和；
- 外格：按该版本的外部位置规则形成的结构数。

第一候选不使用“主运、前运、后运、副运”等预测性别名。

### 21.3 完整计算过程

每格先展示文字、笔画、虚数和算式。用户不展开历史记录，也能独立复核为什么得到该结构数。

### 21.4 逐格历史记录

每格可展开查看数理记录、中性释义、历史短摘、来源、版本差异和局限。

### 21.5 方法与现实边界

页面结尾重复说明该结果不能证明姓名与现实人生之间的因果关系，并提供本次使用的来源索引和版本标识。

- 未支持字符进入 `unsupported`；
- 修改输入使旧结果进入失效路径并禁止导出；
- 失败保留输入并允许重试；
- 不存在人为固定延时。

### 29.4 禁止内容断言

页面、SEO、状态页、结果、导出和测试样例不得把以下内容作为系统结论：

- 分数或总评；
- 三才吉凶；
- 人格性格；
- 健康、寿命、婚姻、事业、财富或家庭预测；
- 性别化分类；
- 改名建议；
- 真实姓名更准确；
- 中国古代或科学验证的虚假背书。

### 29.5 隐私与网络测试

游客和登录状态下都应证明：

- 不读取档案；
- 不请求姓名保存或历史接口；
- 不向第三方发送输入；
- 不写长期浏览器存储；
- 输入不进入 URL、日志和埋点；
- 刷新或关闭后项目自身不恢复草稿；
- 导出在本地完成且默认匿名。

## 31. 推荐迭代顺序

- 自动取名、名字推荐和改名建议；
- 多姓名排名或对比；
- 心理、职业、婚恋、健康和财富解释；
