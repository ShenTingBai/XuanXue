> 状态：Approved — 用户已审阅批准

> 版本：1.1.1
>

>
> 适用范围：基于 XuanXue 现有实现的公开试运行治理、本地打磨、纠错与持续迭代

## 1. 文档目的

本文经用户审阅批准后，作为 XuanXue 用户档案、当次输入、授权、结果历史和删除行为的唯一产品规范。后续页面、接口、数据库、测试和工具数据契约必须与本文保持一致。

XuanXue 已有可运行的产品代码、页面和数据结构，本文不是从零建设新项目的需求书，而是现有项目进入系统性打磨阶段后的目标规范。本文出现的“第一版”均指“本轮打磨完成后形成的首个受治理基线”，不表示项目此前没有开发成果，也不授权脱离现有代码进行整体重写。

本文解决以下问题：

1. 用户为什么提供资料，哪些资料可以长期保存；
2. 档案资料与一次性工具输入如何协作；
3. 输入不完整或精度不足时，系统如何诚实降级；
4. 游客、注册用户和已建档用户分别可以做什么；
5. 保存档案、保存结果、内容偏好为什么必须分别控制；
6. 档案修改、授权撤回、删除和注销后数据如何变化；
7. 第一版本地开发与公开试运行必须满足哪些最低安全边界；
8. 旧数据如何退出，以及实现完成后如何验收。

本文不证明任何传统规则具有现实预测能力。每项工具的输入依赖、计算规则、来源和输出边界必须由对应领域契约定义；紧密相关的轻量工具可以共用一份文档，但领域模型、规则和来源记录仍须分离。

## 2. 已批准的核心结论

1. 一个账号最多只有一个本人档案；产品不存在亲友档案。
2. 注册只创建账号，不自动创建或强迫填写完整档案。
3. 第一版不设置“真实姓名”字段；昵称只用于账号展示，不参与任何计算。
4. 工具默认使用当次草稿，不自动读取、修改或补全本人档案。
5. 用户可主动把本人档案的可用字段复制到当次草稿；缺失字段继续保持为空。
6. 当次草稿的修改不反向覆盖档案。只有用户主动发起“保存到本人档案”，查看差异并确认后才更新。
7. 系统不建立“档案完整度分数”，也不催促用户把所有资料补齐。
8. 第一版不保存婚恋、工作、学习、收入、健康、家庭成员或个人故事等长期现实状态。
9. 系统只可长期保存用户主动选择的内容偏好；当前关注和现实语境默认仅本次使用。
10. 所有未知信息保持未知。禁止猜测、默认补全或从其他字段推断。
11. 游客可以浏览公开内容，并可临时使用已经通过真实性治理的工具；游客资料默认不进入服务器档案或历史。
12. 结果默认不保存。登录用户主动确认后，保存不可变结果快照。
13. 档案修改和规则升级都不能静默重写旧结果。
14. 合婚对方资料仅供本次计算，第一版不保存到任何用户档案或云端历史。
15. 本次计算、保存档案、保存结果和内容偏好是四个不同用途，必须分别说明和控制。
16. 第一版不建设未满十四周岁用户的监护人授权系统，因此不向其提供建档、保存历史或提交个人资料计算的能力。
17. 旧数据库不迁移；新模型实施时采用经过用户确认的一次性本地数据库重建。
18. 当前定义本地开发与公开试运行的最低安全边界，不宣称已经具备公网正式生产资格。

上述结论取代 Raw 记录中与本文冲突的早期设想；Raw 继续保留讨论历史，不再作为当前实现依据。

## 3. 术语与领域边界

### 3.1 账号

账号用于身份验证、会话管理和访问本人保存的数据。账号包含昵称、凭证、安全状态和必要的创建时间，不等于本人档案。

### 3.2 本人档案

本人档案是用户主动长期保存、明确声明属于自己的基础资料。一个账号可以没有本人档案，也最多只能有一个本人档案。

### 3.3 当次草稿

当次草稿是某个工具页面当前使用的输入集合。它可以由用户现场填写，也可以由本人档案复制部分字段得到。它默认只存在于当前页面内存，不等于已保存档案。

### 3.4 内容偏好

内容偏好表示用户愿意看到哪些主题，用于首页模块显示和排序。它不是用户现实状态，也不能作为命理或现实判断依据。

### 3.5 当前关注

当前关注表示用户这次更想了解的方向，只影响已经审核通过的内容区块的顺序或可见性，默认不长期保存。

### 3.6 结果快照

结果快照是用户主动保存的、生成时状态不可变的记录，包含本次实际输入、精度、规则和来源版本、结果、限制说明以及生成时间。

### 3.7 授权凭证

授权凭证只记录用户针对某一用途作出的明确操作及其版本、时间和状态，不重复保存具体出生资料。

### 3.8 他人资料

他人资料是用户在合婚等场景中临时提供、但不属于账号所有者本人的信息。它不是本人档案，也不能因为用户登录而被保存。

## 4. 领域对象必须分离

```text
账号 Account
  │
  ├── 0..1 本人档案 SelfProfile
  ├── 0..n 内容偏好 ContentPreference
  ├── 0..n 授权凭证 ConsentReceipt
  └── 0..n 已保存结果 ResultSnapshot

工具当次草稿 ToolDraft
  ├── 可临时复制本人档案中的相关字段
  ├── 可接受用户本次修改
  └── 默认随离开、刷新或关闭而清除

他人资料 ThirdPartyDraft
  └── 只存在于对应工具的本次草稿，不进入上述任何长期对象
```

账号、本人档案、内容偏好、当次草稿、授权凭证和结果快照不得继续混在同一数据对象中。

当前代码中的 `parent_profile_id`、子档案创建接口、档案切换组件属于历史技术残留，不构成已经批准的产品能力。新模型不保留这些关系。

## 5. 账号与年龄边界

### 5.1 注册

注册只要求创建账号所必需的信息：

- 昵称；
- 登录凭证；
- 隐私与服务规则的必要确认；
- 已满十四周岁的自我声明及其规则版本、确认时间。

注册不要求出生日期、出生时刻、出生地点、传统性别参数或内容偏好。

### 5.2 昵称

- 昵称不是实名；
- 昵称不参与任何计算；
- 昵称不自动写入姓名测试；
- 工具结果不应将昵称称为“命主姓名”或“真实姓名”。

### 5.3 未满十四周岁

第一版不建设监护人身份核验、监护关系核验和监护人授权撤回体系，因此采用能力限制：

- 公开文化内容无需年龄确认即可浏览；
- 游客在首次进入需要提交个人资料的工具前确认已满十四周岁；
- 表示未满十四周岁的访客不能注册、建档、保存历史或提交个人资料计算；
- 本人档案中的出生日期显示用户未满十四周岁时，服务端拒绝保存；
- 不通过身份证或人脸识别进行年龄验证；
- 不使用普通“已取得监护人同意”勾选框绕过能力限制；
- 不保存未通过年龄门槛的出生信息和失败请求正文。

该限制是第一版能力边界，不是对未成年人的价值判断。未来若确需支持，必须先独立设计监护人授权和未成年人个人信息处理规则。

## 6. 本人档案字段规范

### 6.1 总体原则

- 所有字段均按工具实际需要逐步填写；
- 不存在强制填写全部字段的档案向导；
- 不显示完成百分比、健康度或完整度分数；
- 字段未知时保存明确的未知状态，不保存猜测值；
- 页面展示原始输入，计算使用规范化数据；
- 原始输入和规范化数据必须能够相互追溯；
- 工具只读取其数据契约声明的字段。

### 6.2 出生日期与历法

出生日期是一个完整字段组，而不是相互独立的几个文本框。它包含：

- 原始历法：公历或农历；
- 原始年、月、日；
- 农历闰月状态：是、否或尚未确认；
- 规范化公历日期；
- 转换规则或依赖版本；
- 最后确认时间。

约束：

- 选择农历时必须明确闰月状态；
- 日期不完整或不合法时，不能形成正式档案日期；
- 不把历法不明的数据默认认定为公历；输入界面可以先展示公历控件，用户主动填写该控件后才记录公历口径，不要求重复填写两套日期；
- 不把旧数据库中缺少历法说明的日期自动认定为公历；
- 展示结果时保留用户原始历法表达，并说明用于计算的规范化日期。

### 6.3 出生时刻与精度

出生时刻必须先记录“知道到什么程度”，再记录数值：

| 精度状态   | 原始输入         | 可以表达的含义     |
| ---------- | ---------------- | ------------------ |
| 未知       | 无数值           | 用户不知道出生时刻 |
| 仅知道时辰 | 十二时辰之一     | 只确认传统时辰范围 |
| 大致时间   | 一个明确时间范围 | 用户只知道近似范围 |
| 精确时间   | 时、分           | 用户确认到分钟     |

约束：

- “大致时间”必须保存范围或不确定性，不能伪装成精确分钟；
- “仅知道时辰”必须保留为时辰语义，内部适配值不得覆盖原始输入；
- 近似范围跨越规则边界时，不生成唯一的边界相关结果；
- 工具必须按照自身契约判断该精度能解锁哪些区块；
- 不再提示“不确定也请随便填一个大概时刻”。

### 6.4 子时与日期边界

产品不要求普通用户选择流派。档案只保存民用日期、时间原值和用户实际知道的精度，不在资料层生成命盘或决定换日算法：

1. 用户只知道“子时”时，可表达 `23:00–23:59`、`00:00–00:59` 或具体部分未知；未知不能自动填成零点；
2. 工具复制这些原始字段后，按对应单项契约处理边界与支持范围；档案不强制所有工具生成双候选；
3. 八字按其契约保留不同换日约定造成的候选；紫微第一候选按其固定晚子时规则处理，不能唯一落入时辰时拒绝生成；二者不共用一个由档案计算的换日结果；
4. 无法确认的资料保持未知，不让用户挑选“更像自己”的结果来补全档案；
5. 规则层生成的有效日期、实际排盘日和候选结构不能覆盖用户原始民用日期；服务端保存档案也不能预先套用某个工具的算法。

### 6.5 出生地点

第一版地点范围为中国大陆，使用两级结构化选择：

- 第一级：省级地区；
- 第二级：城市或地区；
- 直辖市在第一级选定后自动完成对应第二级；
- 第二级覆盖地级市、自治州、盟、地区及省直辖县级区域；
- 不支持自由文本、地图选点或读取设备当前位置；
- 列表不存在时允许选择“暂不填写”；
- 香港、澳门、台湾和境外地点暂不处理。

档案第一阶段只保存：

- 省级地区代码与名称；
- 城市或地区代码与名称；
- 行政区划数据集版本。

经纬度、IANA 时区标识和历史时区规则必须来自另一份经过核验、带版本的地点计算数据集。行政区划选择本身不能自动解锁完整星盘或所谓真太阳时计算。

### 6.6 传统性别参数

档案不设置通用、强制的性别身份字段。只有经过核验且规则确实需要时，工具才可请求“传统排盘性别参数”：

- 男；
- 女；
- 不提供。

要求：

- 页面说明它是特定传统规则的算法参数，不代表产品对用户身份作出普遍定义；
- 不猜测、不默认；
- 可以仅本次使用，也可以由用户主动保存；
- 八字基础四柱等不需要该参数的结果不得读取它；
- 称骨重量计算第一版移除该无效参数；只有核验出可追溯的男女独立歌诀版本后，才能把它作为“歌诀版本选择”，且不能改变重量计算。

### 6.7 明确不进入本人档案的字段

第一版不长期保存：

- 真实姓名；
- 单身、恋爱、已婚、离异等关系状态；
- 在校、就业、求职、创业等学习或工作状态；
- 学校、专业、单位、职位；
- 收入、资产或其他财务信息；
- 健康状况；
- 家庭成员；
- 完整个人故事；
- 合婚对方或其他人的资料。

此前 Raw 记录中“长期保存关系状态并在九十天后提醒”的设想由本文正式废止。正确治理方式是保持内容中性、按用户当次关注显示，并把未知状态始终视为未知。

## 7. 内容偏好与当前关注

### 7.1 可长期保存的内容偏好

用户可以主动选择愿意看到的主题，例如：

- 学习与成长；
- 工作与规划；
- 人际沟通；
- 亲密关系；
- 日常传统文化。

内容偏好只用于已经审核内容的显示、隐藏和排序。取消偏好后，首页恢复中性排序。

### 7.2 默认仅本次使用的当前关注

工具或首页可以询问“这次更想了解什么”，例如学习、工作、人际、关系或只看基础结构。当前关注：

- 默认只存在于当前页面或会话；
- 不改变事实计算和传统规则；
- 不生成系统原本没有依据的新结论；
- 只调整已经审核通过的区块顺序或显示范围；
- 不反向写入内容偏好，除非用户另行主动保存。

## 8. 渐进式档案工作流

### 8.1 无本人档案

工具不显示无意义的“使用已保存资料”按钮。用户直接填写本次必需字段并计算。

结果生成后，可向已登录用户提供“保存本人资料”入口，但不能弹窗强迫建档。

### 8.2 已有部分档案

工具显示：

> 使用本人档案，可填充 N 项

用户点击后：

- 只复制该工具声明需要且档案中真实存在的字段；
- 未保存字段继续为空；
- 不自动开始计算；
- 不自动修改档案；
- 页面明确显示本次将使用哪些字段。

### 8.3 临时修改

档案记录 `08:00`、用户本次改为 `09:00` 时：

- 当前草稿和结果按 `09:00` 处理；
- 本人档案仍为 `08:00`；
- 页面不出现“已更新档案”的暗示；
- 用户若要长期更新，必须主动进入档案差异确认流程。

### 8.4 主动保存或更新本人档案

保存前展示差异：

```text
新增：出生城市 天津市
修改：出生时刻 08:00 → 09:00
保持：出生日期 2000-01-01
```

用户确认后一次性提交。服务端校验失败时不保存任何部分字段；并返回可定位到具体字段的错误。

## 9. 游客模式

### 9.1 公开浏览

无需登录即可查看：

- 首页与工具说明；
- 规则、来源、版本和争议说明；
- 明确标注的示例结果；
- 不需要个人资料的文化内容。

公开浏览不以同意保存出生资料为前提。

### 9.2 游客临时计算

游客可以使用已经通过真实性治理的工具。输入前明确告知字段、用途和保存状态。

默认行为：

- 草稿只在当前页面内存中存在；
- 刷新、关闭页面或离开流程后清除；
- 不写入浏览器长期存储；
- 不建立服务器档案或历史；
- 不用于画像、推荐或统计；
- 服务端必须计算时，不把完整请求写入数据库和普通日志。

“在本设备暂存草稿”不属于第一版范围。

### 9.3 登录后的数据带入

登录或注册不能自动迁移游客输入。用户可以明确选择“将本次本人资料带入当前页面”，但带入后仍只是草稿。

只有再次主动选择“保存到本人档案”，查看差异并确认后，资料才进入档案。包含他人资料的草稿不提供该入口。

## 10. 按用途分层告知与授权

### 10.1 四类独立用途

| 用途         | 用户动作               | 默认保存 | 可否影响其他用途       |
| ------------ | ---------------------- | -------- | ---------------------- |
| 本次计算     | 阅读就近说明后主动提交 | 否       | 否                     |
| 保存本人档案 | 主动发起并确认字段差异 | 是       | 不代表保存结果         |
| 保存本次结果 | 主动确认结果快照内容   | 是       | 不代表更新档案         |
| 保存内容偏好 | 主动选择偏好           | 是       | 不得用于命理和现实推断 |

不得使用一次注册勾选替代四类具体用途，也不为每个字段制造重复弹窗。

### 10.2 字段就近说明

每个输入组必须可以说明：

- 为什么需要；
- 是否必填；
- 不提供会隐藏或改变什么；
- 当前仅本次使用还是将长期保存；
- 哪些规则或输出区块会读取它。

### 10.3 授权凭证内容

授权凭证至少记录：

- 账号标识；
- 用途编号；
- 数据类别，不记录具体字段值；
- 操作类型；
- 告知或隐私规则版本；
- 操作时间；
- 当前状态与撤回时间。

### 10.4 撤回与删除

- 撤回档案使用：工具以后不再提供档案填充，已复制但尚未提交的草稿立即清除；
- 删除档案字段：删除对应长期值，后续相关结果降级；
- 关闭结果保存能力：停止未来保存，不静默删除已有历史；
- 删除历史：清除已经保存的输入和结果快照；
- 撤回内容偏好：恢复中性内容排序；
- 注销账号：清除账号关联的档案、历史、偏好、授权凭证和活跃会话。

界面必须分别使用“停止后续使用”和“删除已有数据”的准确语言。

## 11. 结果历史与档案关系

### 11.1 默认不保存

结果生成后只在当前页面展示。系统不得因用户已登录而自动调用历史保存接口。

### 11.2 不可变结果快照

用户主动保存时，快照至少包含：

- 工具标识和工具版本；
- 本次实际使用的输入，不复制未使用的整份档案；
- 每个输入的精度、未知状态和来源；
- 规范化计算输入；
- 规则、内容和来源版本及状态；
- 当时允许公开的完整结果区块，不保存已被治理规则隐藏的内容；
- 缺失条件、限制和风险提示；
- 推演所对应的时间；
- 结果生成时间和保存时间。

### 11.3 档案修改不改历史

修改本人档案后：

- 旧结果继续使用保存时的输入；
- 历史页提示其使用的是旧档案信息；
- “使用当前资料重新生成”产生新结果；
- 禁止覆盖原历史或伪装成同一结果。

### 11.4 规则升级不静默重算

旧结果保留原规则版本。若旧规则后来被撤回：

- 历史记录标记为旧版本或已撤回；
- 说明撤回原因、日期和替代版本；
- 不把新结果偷偷写回旧快照；
- 严重错误内容可以停止展示，但必须保留透明的撤回说明。

### 11.5 历史名称

默认名称采用“工具名称 + 生成时间”，例如：

> 八字基础排盘 · 2026-09-03 20:15

不使用真实姓名，也不自动用“事业大旺”“姻缘不佳”等结论作为标题。用户可以主动重命名，名称不参与计算。

## 12. 他人资料与合婚

合婚中的另一方资料必须满足：

- 明确标记为“对方资料”，不叫第二档案或亲友档案；
- 生成前提示用户确认有权提供并用于本次分析；
- 只存在于当前工具草稿；
- 不写入本人档案、内容偏好、授权凭证详情或云端历史；
- 不进入普通日志、错误日志、统计或推荐；
- 离开流程后清除；
- 第一版合婚结果不能保存到服务器历史；
- 可以导出到用户设备，但导出前提示文件可能包含他人信息。

一个确认框不能代替平台的数据最小化责任，因此第一版不提供“长期保存对方资料”或“保存合婚记录”选项。

## 13. 删除矩阵

| 操作             | 本人档案   | 历史快照                   | 内容偏好           | 授权凭证           | 会话     |
| ---------------- | ---------- | -------------------------- | ------------------ | ------------------ | -------- |
| 删除单个档案字段 | 删除该字段 | 保持不变并标记为旧输入     | 保持               | 记录删除事件       | 保持     |
| 删除本人档案     | 全部删除   | 用户明确选择保留或同时删除 | 保持               | 保留最小操作凭证   | 保持     |
| 删除单条历史     | 保持       | 删除对应输入与结果快照     | 保持               | 记录删除事件       | 保持     |
| 清空历史         | 保持       | 全部删除                   | 保持               | 记录清空事件       | 保持     |
| 撤回内容偏好     | 保持       | 保持                       | 删除并恢复中性排序 | 记录撤回           | 保持     |
| 注销账号         | 删除       | 删除                       | 删除               | 删除可识别授权凭证 | 全部失效 |

删除本人档案时，系统必须显示仍含旧出生输入的历史数量，并提供两个明确选项：

1. 删除本人档案，保留历史快照；
2. 删除本人档案，并删除相关历史快照。

若用户选择保留，系统必须说明历史中仍存在保存时的输入，不能暗示所有出生资料已经消失。

## 14. 保存期限

| 数据对象         | 第一版保存期限                     | 到期或终止动作                                    |
| ---------------- | ---------------------------------- | ------------------------------------------------- |
| 当次草稿         | 当前页面存续期间                   | 刷新、离开、关闭或退出登录后清除                  |
| 他人资料         | 当前合婚请求或页面存续期间         | 请求结束且页面离开后清除，不进入长期存储          |
| 账号             | 用户主动注销前                     | 注销时删除账号关联数据并使会话失效                |
| 本人档案         | 用户删除档案、删除字段或注销前     | 按用户选择删除，不因工具使用而延长                |
| 内容偏好         | 用户撤回、删除或注销前             | 删除偏好并恢复中性排序                            |
| 结果快照         | 用户删除单条、清空历史或注销前     | 删除输入与结果快照                                |
| 授权凭证         | 对应账号存续且相关用途仍需证明期间 | 注销时删除可识别凭证；第一版不另建长期归档        |
| 安全事件日志     | 最长九十天                         | 到期自动删除；不得包含完整 IP、出生资料和结果正文 |
| 用户自行导出文件 | 不由服务器保存                     | 由用户在自己的设备上管理和删除                    |

第一版不建立自动云备份。将来增加备份后，必须在启用前另行规定备份周期、访问权限、恢复过程和删除数据从备份中到期消失的期限。

## 15. 第一版的最低安全边界

本章同时约束本地开发和当前 `public_preview`。公开试运行只表示系统可由互联网访问，不表示以下条目已经由现有代码满足；实际控制状态仍须独立审计和验收。

### 15.1 数据位置

- SQLite 数据库只存在于运行实例的私有数据目录，不属于浏览器本地存储，也不得放入公开静态目录；
- 数据库、备份、环境变量和密钥文件不得提交到 Git；
- 第一版不连接云数据库、不自动云备份、不接入第三方用户分析 SDK；
- 文档和 UI 不得宣传尚未实现的静态加密或生产级安全能力。

### 15.2 禁止泄露的位置

出生资料、传统性别参数和他人资料不得出现在：

- URL 和查询参数；
- 普通访问日志；
- 错误堆栈和错误详情；
- 安全事件详情；
- 埋点、分析或推荐数据；
- 使用真实用户资料的测试夹具。

### 15.3 认证与会话

- 登录凭证使用带随机盐的安全哈希，不保存明文；
- 会话令牌随机生成，数据库只保存不可逆验证值；
- 浏览器只通过 `HttpOnly` Cookie 使用会话，登录和注册响应不返回原始令牌正文；
- 生产环境 Cookie 必须启用 `Secure`，并保留合适的 `SameSite`、有效期和退出失效行为；
- 保留登录限流和不暴露账号是否存在的通用错误；
- `SESSION_SECRET` 只来自未提交的环境变量；
- 旧数据库被废弃后，不保留旧版明文 PIN 兼容路径。

### 15.4 服务端校验与权限

- 服务端重新校验日期、历法、闰月、时刻精度、地点代码和字段长度；
- 状态变更接口校验当前账号所有权；
- 请求体设置合理大小限制；
- 数据库操作参数化；
- 多字段档案更新和级联删除使用事务，失败时不保留半完成状态；
- 对重复提交和并发更新返回明确结果，不静默覆盖较新的档案版本。

### 15.5 安全日志

安全日志可记录事件类型、内部账号标识、时间和结果状态，不记录出生资料、完整请求体或结果内容。IP 仅在限流所需的短期范围内使用，不长期保存完整值。

### 15.6 当前未实现的能力

第一版尚未实现出生字段的应用层静态加密、自动备份和完整密钥轮换体系。必须明确记录：

> 当前登录凭证和会话具备基础安全处理，但出生档案尚未提供字段级静态加密，因此本版本不具备公网生产部署资格。

当前系统已经处于公开试运行，因此 HTTPS、字段加密与密钥管理、备份删除、数据恢复、告警、个人信息保护影响评估及安全事件响应不再是抽象的“未来上线事项”，而是必须记录现状、风险与后续验收结果的公开环境缺口。本规范不把这些缺口倒写为已经完成。

## 16. 旧数据库退出策略

新档案模型不兼容旧数据库，不编写旧业务数据迁移或自动推断脚本。实施阶段采用一次性本地数据库重建。

重建属于破坏性操作，执行时必须：

1. 定位并展示数据库绝对路径；
2. 验证目标确属当前 XuanXue 本地数据文件；
3. 说明旧账号、档案和历史都会失效；
4. 由用户决定是否保留一次临时备份；
5. 获得针对该路径的明确执行确认；
6. 重建后验证新库结构、空状态和首次注册流程；
7. 不触碰项目目录以外的任何数据库文件。

旧字段不得自动解释：

- 旧 `birth_date` 不自动认定历法和闰月；
- 旧时、分不自动认定为精确时间；
- 旧地点文本和经度不自动认定为经过核验的结构化地点；
- 旧二元性别不自动转成用户已授权保存的传统算法参数；
- 旧自动保存结果不转成新版本的可信结果快照。

## 17. 模块边界

项目继续采用 Nuxt 3 全栈模块化单体，不新建 Spring Boot 后端、不拆微服务。实现时至少保持以下领域职责分离：

| 模块              | 主要职责                       | 禁止承担的职责                 |
| ----------------- | ------------------------------ | ------------------------------ |
| Account           | 注册、登录、会话、年龄门槛     | 保存出生档案和工具结果正文     |
| SelfProfile       | 本人档案字段、版本、修改与删除 | 保存他人资料、自动执行工具计算 |
| ToolDraft         | 页面当次输入和档案复制         | 默认长期持久化                 |
| Consent           | 用途告知版本、主动操作和撤回   | 重复保存出生字段值             |
| ContentPreference | 内容主题偏好                   | 推断现实身份和改变计算规则     |
| ResultHistory     | 主动保存、快照读取和删除       | 打开历史时静默重算             |
| LocationCatalog   | 版本化行政区划选择             | 未核验地生成经纬度和时区       |
| ToolContract      | 字段依赖、精度门槛和输出降级   | 绕过来源与真实性治理           |

模块通过明确类型和服务接口协作。页面不应继续同时承担档案读取、输入规范化、规则计算、自动保存、历史恢复和授权判断等全部职责。

## 18. 错误与异常行为

### 18.1 输入错误

- 错误定位到具体字段并使用用户能理解的语言；
- 不因一个字段错误清空其他已填内容；
- 不把无效值自动修正为看似合理的默认值；
- 客户端提示不能代替服务端校验。

### 18.2 网络或服务端失败

- 本次计算失败时不创建空历史；
- 档案保存失败时保持原档案不变；
- 结果保存失败时，结果仍可在当前页面查看，但明确显示“未保存”；
- 删除失败时不得先在界面永久移除记录；
- 重试不能产生重复档案或重复历史。

### 18.3 并发与过期页面

- 本人档案具有版本或更新时间校验；
- 旧页面提交覆盖新版本前，必须显示差异并要求重新确认；
- 退出登录后，已打开页面中的本人档案副本和未提交草稿立即清除；
- 会话过期后不能继续调用保存、修改或删除接口。

## 19. 完整验收标准

下列标准全部通过并留存证据后，用户档案模块才能标记为完成。

### 19.1 账号与档案

- [ ] 注册成功后存在账号，但不存在被自动补全的出生档案。
- [ ] 注册不要求出生日期、时刻、地点或传统性别参数。
- [ ] 一个账号最多只能保存一个本人档案。
- [ ] API 和界面均不能创建、切换或保存亲友档案。
- [ ] 昵称不进入任何工具计算输入。
- [ ] 无档案时不显示无意义的“使用已保存资料”。

### 19.2 渐进式填写

- [ ] 只有出生日期时，可保存合法的日期字段组，其他字段保持未知。
- [ ] 工具显示“本人档案可填充 N 项”，N 与实际可用且相关字段一致。
- [ ] 点击填充后不自动计算、不自动保存、不修改档案。
- [ ] 当次修改已填充字段后，档案原值保持不变。
- [ ] 主动保存档案前展示新增、修改和保持字段。
- [ ] 保存失败不会产生部分更新。

### 19.3 日期、时刻与地点

- [ ] 公历和农历原始输入均可追溯到规范化公历日期和转换版本。
- [ ] 农历缺少闰月状态时不能形成正式日期。
- [ ] 未知、时辰、大致范围和精确时间四种状态可被准确保存和恢复。
- [ ] 近似范围跨规则边界时，不生成唯一的边界相关结果。
- [ ] 档案保留子时原值和未知精度，不预先换日；工具按单项契约生成候选或拒绝不支持输入，不诱导用户选择“更像自己”的结果。
- [ ] 地点只能从中国大陆版本化省市数据中选择或暂不填写。
- [ ] 未核验经纬度和时区数据时，地点选择不会解锁完整星盘或真太阳时结果。

### 19.4 传统性别参数

- [ ] 不需要该参数的工具不能读取或要求填写。
- [ ] 需要该参数的工具说明具体使用区块和缺失影响。
- [ ] 不提供时保持未知，不采用男或女的默认值。
- [ ] 称骨重量计算不显示或提交无效性别字段。

### 19.5 游客

- [ ] 未登录用户可以浏览公开内容、来源与示例。
- [ ] 游客输入默认只存在于当前页面内存。
- [ ] 刷新、离开或关闭流程后，游客出生资料不在浏览器长期存储和服务器历史中恢复。
- [ ] 登录后不自动迁移游客资料。
- [ ] 用户明确带入本人资料后，它仍然只是当次草稿。

### 19.6 告知、授权与撤回

- [ ] 输入区可以说明每组字段的用途、必要性、保存状态和缺失影响。
- [ ] 本次计算、保存档案、保存结果、内容偏好具有独立动作和状态。
- [ ] 授权凭证记录用途和版本，但不重复保存具体出生值。
- [ ] 撤回档案使用后，工具不再读取档案，用户仍可临时填写。
- [ ] 撤回内容偏好后首页恢复中性排序。
- [ ] 界面明确区分停止后续使用和删除已有数据。

### 19.7 结果历史

- [ ] 生成结果不会自动调用保存接口。
- [ ] 未登录用户不能产生服务器历史记录。
- [ ] 登录用户保存前看到将保存的输入类别、结果和版本信息。
- [ ] 历史快照只包含本次实际使用的档案字段。
- [ ] 修改档案后旧结果不变，并标记为使用旧输入。
- [ ] 规则升级后旧结果不被静默重算。
- [ ] 删除历史同时删除对应输入与结果快照。
- [ ] 重复点击保存不会产生无法辨认的重复记录。

### 19.8 他人资料与合婚

- [ ] 合婚对方资料不出现在本人档案接口、历史接口、普通日志和安全日志详情中。
- [ ] 合婚结果第一版没有服务器保存入口。
- [ ] 离开合婚流程后无法从账号或其他工具恢复对方资料。
- [ ] 导出前提示文件可能包含他人信息。
- [ ] 未满十四周岁的双方资料均不能提交。

### 19.9 年龄限制

- [ ] 公开浏览不强制收集年龄或身份证。
- [ ] 游客首次提交个人资料前必须确认已满十四周岁。
- [ ] 注册和首次保存个人资料前存在已满十四周岁声明。
- [ ] 明确表示未满十四周岁时不能注册、建档、保存历史或提交个人资料计算。
- [ ] 出生日期与年龄声明冲突时拒绝保存，并且不在日志中记录完整日期。
- [ ] 不存在普通监护人勾选框绕过路径。

### 19.10 删除与注销

- [ ] 删除本人档案前显示仍包含旧输入的历史数量。
- [ ] 用户可以明确选择保留历史或同时删除。
- [ ] 选择保留时，界面说明历史仍包含保存时输入。
- [ ] 注销后档案、历史、偏好和会话均不可访问。
- [ ] 多对象删除在事务失败时不会留下半删除状态。

### 19.11 安全边界

- [ ] 数据库、环境变量以及本地或服务器备份均被 Git 忽略，且数据库不在公开静态目录。
- [ ] 登录凭证没有明文存储，旧明文 PIN 兼容路径已随旧库退出。
- [ ] 原始会话令牌不在数据库和登录响应正文中出现。
- [ ] 出生资料不出现在 URL、访问日志、错误详情和安全事件详情中。
- [ ] 服务端对全部档案字段重新校验。
- [ ] 越权访问他人档案或历史返回拒绝，且不泄露记录内容。
- [ ] 文档明确当前版本未提供出生字段静态加密，公开试运行不等于具备公网正式生产资格。

### 19.12 移动端与可访问性

- [ ] 320、360、390、414 CSS 像素宽度均可完成填写、查看用途、差异确认、删除和撤回。
- [ ] 200% 文本缩放下无字段重叠、横向自由滑动或关键按钮不可见。
- [ ] 不通过禁用浏览器缩放掩盖布局问题。
- [ ] 所有表单控件具有可读标签、错误关联和键盘操作路径。
- [ ] 日期、时间和地点组件在移动端保留当前墨韵视觉风格，但使用标准语义控件和服务端校验。

### 19.13 旧数据库重建

- [ ] 重建前展示并核对数据库绝对路径。
- [ ] 用户对该路径和数据丢失范围作出明确确认。
- [ ] 不执行旧字段自动推断或业务数据迁移。
- [ ] 重建后数据库为空且结构符合新规范。
- [ ] 首次注册、渐进建档、主动保存与删除流程全部重新通过。

## 20. 明确不在本规范第一版范围内

- 多本人档案、亲友档案或家庭成员管理；
- 真实姓名字段；
- 婚恋、工作、学习等长期现实状态档案；
- 监护人身份与授权系统；
- 香港、澳门、台湾和境外地点数据；
- 浏览器长期草稿恢复；
- 合婚对方资料和结果的服务器保存；
- 平台 AI、用户故事长期保存或服务端 API Key 托管；
- Spring Boot 独立后端、微服务或多实例部署；
- 出生字段静态加密和自动云备份；
- 正式生产发布、宣传运营、应用上架和备案方案。
