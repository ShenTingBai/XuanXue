## 4. 分类规则与字段解释

> 第 3 章是唯一可机读规范账本；本章只解释分类规则与字段含义，不再复制第二套分类表。原第 4 章「证据与来源分类矩阵」（A-/B-/…/J- 缩写 ID 六列表）的每条决策已展开并入第 3 章账本的 content_class、source_status、source_locator、source_note、disposition、disposition_rationale 六列。

### 4.1 content_class（内容分类，4 种）

- `fact_recomputable`：可复算事实——同一输入 + 明确算法（确定性编码/查表/工程公式/披露文本/保存恢复行为）可逐位复现输出。判断规则：给定相同输入与相同代码版本，输出可复算；披露文本与实现一致。
- `traditional_classification`：传统分类——传统理论体系的分类/标签/文本（神煞吉凶、太岁关系、81 数理、十二值星、纳甲装卦、黄道十二宫、称骨权重等），且存在来源定位（代码常量、引注或溯源文案）可供后续核验；是否已核验由 source_status 单独表达。
- `public_cultural_interaction`：公共文化互动——内容按日期/公共历法确定、同日全体用户相同（相同性）；或为公开的非随机/确定性选取（随机性公开）；或为不针对用户个人信息的公共提示（非个人预测）。归类时必须说明满足哪一条（见各条 source_note 与 disposition_rationale）。
- `unsupported_or_untraceable`：无支持或不可追溯——营销玄学措辞、模板化现实叙述与后果建议、工程权重评分数字展示、自编释义文本、未满足输入条件的默认值补全等。disposition_rationale 中必须写明不能公开保留的具体原因。

### 4.2 source_status（来源状态，6 种）

- `verified_primary_or_official`：经人工对照官方/一手文献核验通过。
- `verified_academic_secondary`：经人工对照学术二手文献核验通过。
- `traceable_implementation_only`：仅实现可追溯——代码路径、算法、常量可定位，但其依据的传统/民俗/典籍内容未经核验。
- `unverified_reference`：未核验引用——代码中存在来源引注（注释、溯源文案），但未对照通行本核验、无版本页码。
- `no_source`：无来源——无任何引注或出处声明。
- `not_applicable`：不适用——该内容不依赖传统文献引述（公历/农历/节气等历法标签显示、工程推导规则、站点自编条目池）。

**本次审计未新增任何 verified 来源**：账本中不存在 verified_primary_or_official 与 verified_academic_secondary 条目。代码注释、README、网页转述、网页搜索整理均不算已验证来源——它们至多构成 unverified_reference（有引注待核验）或 no_source（无引注）。

### 4.3 disposition（处置建议，4 种）

- `retain`：保留——fact_recomputable 且披露完整；或传统分类/公共文化内容已有准确披露、无现实后果断言。
- `relabel`：重新标注或改写框架——为传统说法/民俗/占星/娱乐内容补框架标注，或将营销措辞改写为可核验表述，或修正与实现不符的披露文字。
- `downgrade`：弱化数字、降级展示——工程权重 0-100 评分等数字展示需弱化并就近标注工程校准。
- `hide`：隐藏——未披露工程校准的评分等按产品边界不接受的内容。

使用规则：disposition 必须与 content_class、source_status、输入完整度一致——fact_recomputable + traceable_implementation_only 通常 retain（例外：输入条件缺口如 guming 默认值补全 → relabel）；unsupported_or_untraceable 不得 retain；hide 仅用于未披露校准的评分；no_source/unverified_reference 的传统或民俗内容必须 relabel 或 hide。所有 disposition 均为供下一阶段规划使用的建议，不是已实施的变更。
