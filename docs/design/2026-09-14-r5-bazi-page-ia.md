## 1. 页面定位：这一版靠什么撑住

R5 首批输出是**闭集**（交付规范 §7.1，D1 裁决）：公历农历对照、年柱/月柱/日柱、三柱天干地支与基础五行、日干、规则/引擎/来源集合版本与限制说明。

**三柱本身只有 6 个字。** 因此本页的内容量不在"结论"，而在**三件事**：

1. **为什么是这 6 个字**——干支怎么来的、月柱为什么这样切、边界为什么可能不确定、缺了什么；
2. **哪些话不能说**——明确列出未输出的内容清单，以及本页不做的推断；
3. **依据是什么**——逐条回到可核对的来源与规则版本，并如实标注精度与证据等级。

这与产品定位（可追溯的传统规则探索，不是命运测评）一致，也是本页唯一站得住的"厚度"来源。**不得**通过补十神/藏干/纳音/大运/流年/评分来填充页面（那是后续阶段的事，且多数来源尚未核验）。

## 2. 骨架：六段语义顺序

治理规范 §4.1–4.7 规定六段且**要求 DOM 阅读顺序**如此；契约 §22 的八项顺序是内容建议，层级低于治理规范（消歧记录 C9 裁决）。故采用：

| 段                   | 治理规范 | 契约 §22 对应内容                                    |
| -------------------- | -------- | ---------------------------------------------------- |
| Ⅰ 工具说明           | §4.1     | 工具说明（本页是什么、能/不能回答什么）              |
| Ⅱ 本次操作           | §4.2     | 本次输入与结果状态（输入区）                         |
| Ⅲ 核心结果摘要       | §4.3     | 本次输入与结果状态（状态横幅 + 摘要）                |
| Ⅳ 通俗解释与详细结果 | §4.4     | 四柱基础结果（本版为三柱）、怎样看懂这张盘、日期对照 |
| Ⅴ 依据与范围         | §4.5     | 来源、规则版本和限制                                 |
| Ⅵ 本次结果操作       | §4.6     | 主动保存；历史入口（导出不在 R5，D4）                |

页面外壳沿用既有工具页 `ToolPageLayout`（**只填默认内容槽**：无 `#nav`、无 `#mobile-nav`、无 `#nav-right`，以免在正文前插入跨工具导航而破坏六段 DOM 顺序）。保留 `ScrollTopButton`。

## 3. 逐段设计

### Ⅰ 工具说明（治理 §4.1）

- 一句话定位：**"按出生日期排出年、月、日三柱，并说明每一步的依据、边界与限制。"**
- 明确"能回答"：公历与农历怎么换算；三柱为什么是这些干支；边界日为什么会有多个可能结果；缺少什么。
- 明确"不能回答"（**照抄进页面，不软化**）：不输出时柱、大运、流年、流月、神煞、日主强弱、喜用神、评分、性格判断与现实预测；不显示胎元、命宫、身宫。
- 当前状态提示（D3 方案 B）：内部验证中，未公开；只有被授权的账号可访问。文案不承诺发布日期。

### Ⅱ 本次操作（治理 §4.2）

- 默认**公历**三件（年/月/日）；点击"我只知道农历出生日期"后切换为农历三件 + **闰月开关**（默认未选，必须显式选择；不得默认普通月，契约 §7.2）。
- **十四周岁声明**：提交个人日期计算前需确认已满十四周岁；未满则不给个人计算，但保留公共说明阅读（数据规范 §5.4）。
- 范围与校验：下界 `1901-01-01`（含），上界为 `asOfDate`（当前北京时间日期）；越界的错误**就近显示在输入区**，并说明能否修正、输入是否保留（治理 §7.3）。
- **无任何默认值**：不预填今天、不预填零点、不预填示例日期。
- 就地说明每个输入组（数据规范 §10.2）：为什么需要、是否必填、不提供会怎样、仅本次使用还是长期保存、哪些输出会读取它。
- 草稿只存在页面内存：不写 `localStorage`/`sessionStorage`/URL/日志；刷新或离开即清除。
- 修改任一输入后，已有结果立即标记为 `stale`（"输入已修改，结果尚未更新"），**保留旧结果、不自动重算**（治理 §7.4）。
- 档案带入（**待确认项 Q2**）：若纳入，则提供"从本人档案带入出生日期"开关，显式复制并按数据规范 §8.3 展示带入来源；档案被删除后开关自动失效并提示。

### Ⅲ 核心结果摘要（治理 §4.3）

**状态必须在摘要之前**显示（治理 §4.3）。状态文案词典：

| 状态                                               | 用户可见文案                                             | 依据                                           |
| -------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------- | ------------- |
| `phase = success` + `successQualifier = partial`   | 「已生成日期级结果：三柱（年、月、日）／共四柱，缺时柱」 | D6：完整性分母写明 3/4                         |
| `phase = success` + `successQualifier = candidate` | 「该日期跨〈立春                                         | 某节〉，年柱/月柱有 2 种可能，见下方逐项对比」 | 交付规范 §7.2 |
| `freshness = stale`                                | 「输入已修改，结果尚未更新」+ 旧结果所用输入摘要         | 治理 §7.4                                      |
| `failureCategory = invalid_input`                  | 「日期无效：〈具体原因〉」+ 保留输入                     | 治理 §7.3、契约 §26                            |
| `failureCategory = unsupported_input`              | 「超出当前支持范围（1901-01-01 至今）」                  | D9                                             |
| `failureCategory = engine_error`                   | 「历法计算未完成，未生成任何默认结果」                   | 契约 §26：不得回退默认                         |
| 保存失败                                           | 「本次结果仍未保存」+ 可重试                             | 交付规范 §7.4                                  |

摘要同时列出**限制与缺失**：缺时柱（因此不生成时柱相关任何内容）、不支持 23:00–23:59 子初换日候选、节气时刻精度声明（见 §5）。

### Ⅳ 通俗解释与详细结果（治理 §4.4）

1. **三柱卡片**：年柱 / 月柱 / 日柱，各显示干支、天干五行、地支五行；**日干**单独标注（称谓见 §6 措辞表）。不显示十神、藏干、纳音、强弱、喜忌。
2. **候选逐项对比**（仅当 `candidate`）：并列展示**每个完整情形**（年柱+月柱整组），每项带文字原因（"立春前（当日 00:00 至 04:02）"），**不得只用颜色区分**（契约 §22.1）。情形数**不得叉乘**（规则台账 R-BZ-008）。
3. **日期对照**：用户原始表达 → 规范化公历 → 对应农历（含闰月状态）→ 转换规则版本。
4. **怎样看懂这张盘**（契约 §17 六问，逐术语三层）：
   - 干支是什么 → 用户得到什么 → 怎样算/查 → 在本页的作用 → **不代表什么** → 用了哪版规则与来源；
   - 覆盖：干支、年柱、月柱（为何以"节"为界）、日柱与日干、边界候选为何不确定、缺时柱意味着什么；
   - 三层组织：默认一句白话 / 用户主动展开的计算说明 / 来源、规则版本与限制。
5. 详细内容放**每柱下方的正常文档流折叠区**；不使用浮动"注"按钮或覆盖式说明（契约 §22、治理 §3.11）。

### Ⅴ 依据与范围（治理 §4.5）

必须逐条列出，且**沿用证据包的措辞等级**：

- **来源清单**（可点击到台账定位）：
  - 公历/农历编排与干支纪日锚点：GB/T 33661—2017《农历的编算和颁行》§4.1—4.5、§5.2、§6.3.2、附录 A（**国家标准**）；
  - 节气日期（1901—2100 逐日）：中国香港天文台公历与农历对照表（**政府机构公开数据**）；
  - 节气时刻：日本国立天文台《暦要项》二十四节气（**国家天文机构官方历书**）；
  - 年柱/月柱传统规则：《三命通会》卷二·论遁月时（五虎遁）、卷二·论四时节气（**通行广本在线整理本；底本未与影印核对**）；
  - 干支五行：复用生肖阶段已核验的《三命通会》卷二·论天干阴阳生死、《五行大义》卷二·第五论配支干。
- **版本**：规则版本 `2026-09-14-bazi-date-v1`、来源集合版本同值、引擎名与版本（历法库，仅作实现工具）。
- **限制说明**（逐条如实）：
  - 节气时刻已对抽样年份完成分钟级核验，**国标 §5.2 要求的 1 秒级精度未核验**；
  - 传统规则维度目前**只到在线整理本层级**，尚未完成原刻影印核对；
  - 支持范围下界 1901-01-01，上界为查询当日。
- **未输出内容清单**（同 §1）。
- **精度与不确定性**：若某"节"的时刻距午夜小于阈值（如 5 分钟），页面必须显式提示该边界迫近日界、候选判断对该精度敏感（对应 GAP-BZ-005/006 的残余风险）。

### Ⅵ 本次结果操作（治理 §4.6、交付规范 §7.4）

固定顺序，页面上按此实现：

```text
生成结果 → 未保存
  → 用户点击「保存本次结果」（stale 时该按钮禁用并说明原因）
  → 游客在当前页面完成登录/注册（复用 AuthDialog，认证成功本身不触发保存）
  → 展示本次保存摘要：输入类别、结果内容、保存时间与规则版本、含敏感出生日期、如何查看与删除、不会更新本人档案
  → 用户再次确认
  → 服务端用同一领域规则复算并核对
  → 创建不可变快照 → 已保存
```

- 幂等：同一次生成有稳定 `resultId`；同一 `resultId` 重复保存只产生一条记录；网络重试不产生重复（治理 §11.6）。
- 客户端结果与服务端复算不一致 → **拒绝保存**，保留页面结果并明确显示"未保存"（交付规范 §7.4）。
- **不做导出**（D4）。
- **历史入口**：列表以「八字基础排盘 · 保存时间」命名（消歧记录 C4 裁决），显示安全摘要（不含精确出生日期）与保存时间；打开历史**只读快照、不静默重算**；「用当前规则重新计算」= 把旧快照输入复制成新的当次草稿并生成**未保存**结果，原记录不变（D8）；支持删除单条、在显示条数后确认清空全部八字历史；删除失败时**不提前从界面移除**（交付规范 §7.5）。

### 档案删除联动（D5，交付规范 §7.5 + 数据规范 §13）

`/self-profile` 的危险区在删除本人档案前，必须：

1. 显示**仍含出生输入的历史条数**（数量为 0 时不显示该选择）；
2. 提供两个明确选项：**保留历史快照** / **同时删除相关历史快照**；
3. 选择保留时明确说明"历史快照中仍包含保存时的出生输入"，**不得**暗示所有出生资料已消失。

## 4. 数据流与边界

```text
游客/内部账号
  输入(内存草稿) → 归一化 → 历法适配器 → 三柱计算(带版本) → 页面结果
                                        ↑ 不调用第三方库（契约 §11）
  生成过程不向服务器提交出生日期

保存（登录后显式触发）
  页面结果(含原始输入) → POST → 服务端校验身份/同源/字节数 → 同一领域规则复算
    → 与客户端结果核对 → 一致则写不可变快照；不一致则拒绝
```

- 出生日期不得出现在 URL/查询参数、普通日志、错误详情、安全日志、埋点（数据规范 §15.2、§15.5；交付规范 §3.2）。
- `/api/result-history`、`/api/self-profile` 一律 `Cache-Control: no-store`，Service Worker 走 NetworkOnly（交付规范 §3.2）。
- 越权访问他人历史返回拒绝且不泄露内容；会话过期后不能继续保存/删除。

## 5. 措辞红线（来自证据包，页面文案不得越过）

| 不得出现                                       | 原因                                                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| "国家标准规定八字年柱以立春为界"               | 国标规定的是**农历**干支年（正月初一交替）；立春口径来自传统规则，且我们只有条文推导（GAP-BZ-001） |
| "古籍明文规定/原典已核验"                      | 传统规则载体是在线整理本，底本未与影印核对（GAP-BZ-007）                                           |
| 任何现实预测、性格、婚恋、事业、财富、健康断言 | 治理 §15.3、契约 §27.3                                                                             |
| 0–100 分、吉凶等级、红绿排序、伪精确五行比例   | 治理 §21.2、契约 §16                                                                               |
| "时柱将在……推出"等日期承诺                     | 治理 §20.4 不承诺虚假发布日期                                                                      |
| 把历法事实与规则差异混成一句                   | 契约 §4：历法计算事实 / 传统分类 / 规则差异必须可区分                                              |

**称谓**：主标签用「日干」；首次出现时在六问里说明它在传统体系中亦称「日主」（消歧记录 C11）。**内容标签**：用户可见标签采用治理 §5.6；R5 实际只用到「计算结果」与「项目整理」两类（消歧记录 C10）。

## 6. 移动端与可访问性

- 320 / 360 / 390 / 414 CSS px 与 **200% 文本缩放**下完成输入、生成、阅读、保存、历史查看与删除（治理 §18.1、交付规范 §8.4）。
- 三柱在 320px 下不产生页面横向滚动；高密度内容只允许**组件内局部**横向滚动并给滑动提示与等价文字摘要（治理 §18.3）。
- 触控目标 ≥44px；错误不只短暂闪现；展开区不用易裁剪的固定 `max-height`（治理 §18.1）。
- 每页唯一 `h1`；每个输入有可见 `label`；必填与错误不只依赖颜色（治理 §19.1）。
- 弹层（AuthDialog、保存确认）：初始焦点进入、Escape 关闭、Tab 不进入背景、关闭后焦点返回触发按钮、移动端近全屏（治理 §19.2）。
- 历史条目用普通列表中的按钮/链接，**不误用 `listbox`**（治理 §19.2）。
- 不禁用缩放、不用全局 `overflow: hidden` 掩盖问题（项目配置禁止项）。
