# 账号与档案的信息架构调整设计（2026-09-13）

> 用户提出的原始问题：「取消账号设置页面，把账号设置并进本人档案？」
> 讨论后用户确认的三个痛点：① 注册后的落脚点不对；② 账号页太薄、跳转麻烦；③ 两套视觉语言不统一。
> 本文是方向 B 的设计基线；实现与验收见文末链接。

## 1. 事实与约束（先于设计）

| 约束                                                                                 | 出处                        | 对设计的影响                                           |
| ------------------------------------------------------------------------------------ | --------------------------- | ------------------------------------------------------ |
| 账号=身份验证/会话/访问本人数据，**不等于本人档案**                                  | 数据生命周期规范 §3.1、§3.2 | 两页可以存在，但不要在同一区混放两类操作               |
| 账号、档案、偏好、草稿、凭证、快照**不得混在同一数据对象**                           | 同上 §4                     | 合并页面不违反数据层分离，但会弱化边界的产品表达       |
| **注销账号**：档案+历史+偏好全删、全部会话失效；**删除本人档案**：会话与其他数据保留 | 同上 §13 删除矩阵           | 两个"删除"的爆炸半径不同，**不得同区相邻**             |
| 普通退出只终止当前会话；可提供"退出所有设备"；不建设设备列表                         | 同上 §5.3                   | 账号页会话节只放两个动作 + 说明                        |
| 注册不自动建档                                                                       | 同上 §19.1                  | 注册后落到"尚未录入出生资料"的空态是符合规范的落脚点   |
| 昵称 2–20 字符、注册后不可修改、不参与计算                                           | 同上 §5.2                   | 账号页只读展示 + 规则说明                              |
| 原型账号菜单为三项：账号设置 / 本人档案 / 退出登录                                   | `xuandao-self-profile.html` | 保留独立账号入口，退出登录保持全局可达                 |
| R2 已接受，账号页浏览器流程有验收记录                                                | 阶段路线图 R2               | 改动后需重跑退出当前设备 / 退出所有设备 / 注销三条流程 |

## 2. 决策（方向 B）

**保留两个页面，重新划分职责**，不做完全合并。

1. **登录后的落脚点改为 `/self-profile`**：登录、注册、会话恢复成功、旧档案链接重定向均指向本人档案页；`/account` 路由保留，不再作为落脚点。
2. **`/account` 重做为出版版「账号与安全」**，与本人档案页同一套版式语言，内容做实（见 §3）。
3. **顶栏账号菜单保持三项**（账号与安全 / 本人档案 / 退出登录），退出登录在任何页面一次可达。
4. **两条守住的边界**：注销账号不与"删除整份档案"同区；账号与会话操作不依赖"必须先打开某个数据页面"。

## 3. 「账号与安全」页内容（全部真实来源，不造功能）

| 节           | 内容                                                                                                                                         | 来源                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Ⅰ 账号       | 昵称（不可修改）、昵称规则说明（2–20 字符、注册后不可修改、不参与计算）、创建时间、账号状态                                                  | `currentAccount`；规范 §5.2                                                                 |
| Ⅱ 会话       | 每台设备独立会话、七天有效期、退出当前设备 / 退出所有设备的说明与动作                                                                        | 规范 §5.3；`SESSION_DURATION_DAYS`                                                          |
| Ⅲ 数据与告知 | 本人档案状态摘要（已保存出生日期 / 尚未录入）+ 进入档案页；隐私政策与服务规则**真实版本号**并链接全文；档案授权与用途位于档案页 Ⅱ/Ⅲ 节的说明 | `useSelfProfile.summary`；`CURRENT_PRIVACY_POLICY_VERSION`、`CURRENT_SERVICE_TERMS_VERSION` |
| Ⅳ 注销账号   | **独立危险区**（默认折叠）：删除账号并使其全部会话失效；昵称 + 密码复核弹层                                                                  | 规范 §13；现有 `deleteAccount` 逻辑不变                                                     |

## 4. 复用与重构（避免两页分叉）

- 把出版版外壳提升为全局类（`main.css`，登记进设计系统）：`editorial-shell`、`editorial-article`、`editorial-section`、`editorial-section--first`；
- `ProfileMasthead` 泛化为纯展示（`edition` / `title` / `subtitle` / `statusText` / `updatedText`），两页共用；
- `ProfileIndexNav` 增加 `footnote` 属性（两页卷目脚注不同）；
- 新增 `ProfileNote`（提示条）与 `ProfileDangerSection`（危险区外壳 + 插槽），`ProfileDangerZone` 改为使用外壳，账号页注销区复用同一外壳。

## 5. 影响面与代价

- 页面：`pages/account.vue`（重做）、`pages/login.vue`（3 处跳转）、`pages/profile/[id].vue`（重定向目标）、`pages/index.vue`（游客 CTA 的账号入口改为「登录 / 注册」指向 `/login`，不再指向一个游客打不开的页面）；
- 组件：`ProfileMasthead`、`ProfileIndexNav`、`ProfileUsageSection`、`ProfileScopeSection`、`ProfileDangerZone` + 2 个新组件；
- 测试：`tests/pages/auth-content.test.ts`、`tests/pages/index-content.test.ts`、`tests/components/profile-editorial.test.ts` 需按新结构更新；新增账号与安全页测试；
- **验收代价**：R2 已验收的账号页三条流程（退出当前设备 / 退出所有设备 / 注销）需要在改动后重跑真机验收。

## 6. 非目标

- 不取消 `/account` 路由（旧链接不 404）；
- 不把"注销账号"并入档案页的危险区；
- 不改认证、会话、注销的 API 与 `useAuth` 逻辑；
- 不新增凭证找回、邮箱/手机号绑定、设备会话列表（规范明确第一版不做）；
- 不改本人档案页的数据与交互，仅共用外壳样式；
- **页脚统一**：`/self-profile` 补齐全站 `PageFooter`（2026-09-13 用户要求；此前只有账号页有页脚，与全站其它页面及工具页不一致）。

## 7. 验收标准

- 登录/注册/会话恢复后进入 `/self-profile`；`/account` 与旧 `/profile/[id]` 不再作为落脚点；
- 账号与安全页四节齐备，昵称/时间/状态/两个版本号均为真实数据；
- 注销仍在独立危险区，需昵称 + 密码复核，失败不提前清状态；
- 退出当前设备只终止当前会话、退出所有设备终止全部会话、注销使全部会话失效（真机重跑）；
- 320/360/390/414 CSS px × 16px/32px 无横向溢出；320px + 200% 弹层可滚动、按钮可达；
- `typecheck` / `test` / `lint` / `build` / `prettier --check .` 全部通过；乱码检测无新增命中。

## 8. 落地结果

已按本设计实施并通过真机验收 **32/32**（测试 67 文件 / 2379 例）。落地过程中的实际差异（页名与菜单文案同步改为「账号与安全」、两页统一保留全站页脚）、两处测试断言的重构理由，以及**顺带修掉的页面级弹层无样式缺陷**，见 [账号与档案信息架构调整验收](../audits/2026-09-13-account-and-profile-ia-acceptance.md)。
