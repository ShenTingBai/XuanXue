> 用途：把本文件整份交给设计工具，作为它设计「八字基础排盘」页 UI 原型的输入。
>
> 日期：2026-09-15 ｜ 现状版本：`/tools/bazi`（R5-B 已实现，内部验证版）
>
> 设计系统全文：`docs/design/design-system.md`（本文件只摘录与约束，冲突时以设计系统与产品规范为准）

---

## 0. 一句话目标

在**不改内容范围、不改六段结构**的前提下，重新设计这一页的**视觉层级与阅读体验**，让「只有 6 个字的结论」也能被专业、可信、好读地呈现出来。

这页的难点不是"排版好看"，而是：**内容少、约束多、还要显得不空洞**。设计手段应集中在层级、留白、质感、状态表达上，而不是靠加内容填充。

---

## 1. 这是什么页面

- 用户：已登录且被授权的内部验证账号（当前不公开）。
- 做什么：按出生日期排出**年柱、月柱、日柱**（即 6 个字 + 各自五行），并说明依据、边界与限制。
- 定位：可追溯的传统规则探索工具，**不是命运测评**。
- 内容范围（已冻结，不得扩大）：公历农历对照、年月日三柱、天干地支基础五行、日干（亦称日主）、规则/引擎/来源版本、限制说明、未输出内容清单。
- 明确**不输出**：时柱、大运、流年、流月、神煞、日主强弱、喜用神、忌神、评分、性格判断、现实预测、胎元、命宫、身宫。

---

## 2. 硬约束（不可改动）

1. **六段 DOM 顺序固定**，不得调换、合并或新增段落：
   Ⅰ 工具说明 → Ⅱ 本次操作 → Ⅲ 核心结果摘要 → Ⅳ 通俗解释与详细结果 → Ⅴ 依据与范围 → Ⅵ 本次结果操作。
   视觉上可以重组层级，但**阅读顺序（DOM 顺序）必须保持**。
2. **状态先于摘要**：Ⅲ 段的状态说明必须出现在结果摘要之前。
3. **不得使用覆盖式说明/浮动「注」按钮**：所有解释性内容进入正常阅读流（折叠区用原生 `details`）。
4. **不得把换算结果显示成用户输入**：日期对照里必须能区分「你填写的」与「依规则换算的」。
5. **不得用颜色作为唯一区分手段**：候选情形、状态、错误都必须同时有文字/图标语义。
6. **不得用固定 `max-height`** 的展开区（放大字体时会被裁切）。
7. **不得出现分数、等级、红绿排序、吉凶、预测、性格/事业/健康/婚恋断言**。
8. **不得承诺发布日期**（例如"时柱将在……推出"）。
9. 措辞红线（原文照抄，不得越线）：
   - 不得写「国家标准规定八字年柱以立春为界」——国标规定的是**农历**干支年（正月初一交替）；以立春为年界是**传统规则**、由本项目采用。
   - 不得写「古籍明文规定 / 原典已核验」——传统规则目前只到古籍**在线整理本**层级，原刻影印核对未完成。

## 3. 设计系统（必须使用，不要新建色板/字体）

- **墨/纸/朱砂/金/玉** 色阶与**五行色**：见 `docs/design/design-system.md` §2；五行配色必须取 `constants/bazi.ts` 的 `WUXING_COLORS`，回退 `WUXING_FALLBACK_COLOR`。
- 颜色处理**硬规**：用 `color-mix(in srgb, var(--color-x) N%, transparent)`，**禁止** `rgba(...)` 与 Tailwind 的 `bg-x/10` 这类 opacity 写法（多层叠加卡片会失真）。
- 字体：`font-display`（马善政/楷体）只用于标题与大字数据；`font-sans` 用于正文、标签、按钮。正文最小 `text-sm`，辅助最小 `text-xs`。
- 既有可复用类（**优先复用，不要另造**）：`card-warm`、`card-paper-solid`、`tool-card`、`btn-seal` / `btn-cin` / `btn-ink` / `btn-ghost` / `btn-quiet` / `btn-solid`、`input-ink`、`section-header`、`seal-icon`、`divider-ink`、`scroll-hint-x`、`editorial-dialog-*`。

## 5. 必须覆盖的状态（缺一个都不算完整稿）

| 状态                                              | 用户看到什么                                                                        |
| ------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 初始                                              | 无任何默认值：年月日全空、闰月未选、十四周岁未勾、生成禁用并说明原因                |
| 处理中                                            | 生成中（`processing`）                                                              |
| 成功·日期级（partial）                            | 「已生成日期级结果：三柱（年、月、日）／共四柱，缺时柱」＋三柱卡片                  |
| 成功·跨节（candidate）                            | 「该日期跨〈某节〉，年柱与月柱各有 2 种可能」＋**恰好两个完整情形**并列＋日柱仍唯一 |
| 已过期（stale）                                   | 「输入已修改，结果尚未更新」＋旧输入摘要；**旧结果保留在页面上**，保存入口禁用      |
| 失败·日期无效                                     | 「日期无效：〈原因〉」＋输入已保留、可就地修正                                      |
| 失败·超出范围                                     | 「超出当前支持范围（1901-01-01 至今）」                                             |
| 失败·引擎未完成                                   | 「历法计算未完成，未生成任何默认结果」（不得回退默认值）                            |
| 保存失败                                          | 「本次结果仍未保存」＋可重试；**页面结果不消失**                                    |
| 已保存                                            | 「本次结果已保存（时间），重复保存不会产生第二条记录」                              |
| 历史空态 / 列表 / 快照只读 / 清空确认（显示条数） | 列表项只显示保存时间与概况，**不显示出生日期**                                      |
| 档案带入                                          | 入口按钮 → 空草稿直接带入 / 有冲突时替换确认（显示当前值与拟带入值）→ 可撤销        |
| 边界提示                                          | 交节时刻距午夜 < 5 分钟时提示「该边界迫近日界，判定对精度敏感」                     |

## 6. 交互与可访问性（硬要求）

- 触控目标 ≥ 44px；`focus-visible` 用 2px 朱砂描边（offset 2px）。
- 弹层（保存确认、认证）：初始焦点进入、Escape 关闭、Tab 不进入背景、关闭后焦点返回触发按钮、≤480px 近全屏。
- 自定义 radio/checkbox：`sr-only` input + 样式化 span，focus 环用 `.sr-only:focus-visible + span`。
- 每页唯一 `h1`；每个输入有可见 `label`；必填与错误不只靠颜色。
- 展开/收起必须适配 `prefers-reduced-motion`。
- 320 / 360 / 390 / 414 CSS px 下不得出现页面级横向滚动；高密度内容只允许**组件内**局部横向滚动并给滑动提示与等价文字摘要。
- **320px + 200% 文本缩放**下：正文仍可读、控件仍可达、无横向溢出（这一档当前实测通过，新稿不得回退）。

## 7. 交付物要求（否则不可实施）

1. 桌面端 + 移动端（至少 390 / 320 两档）完整稿。
2. 上述**全部状态**的稿或状态说明。
3. 标注：层级与间距、字号、颜色 **token 名**（不是任意色值）、以及**对应到第 4 节哪个组件**。
4. 明确写出：哪些既有类被复用、哪些地方需要新增类（新增类需要同步写进 `docs/design/design-system.md`，这是本项目的硬规）。
5. **不要**直接给可覆盖实现的 HTML/CSS 成品——请给结构 + 令牌 + 状态，落地由我按设计系统实现。
