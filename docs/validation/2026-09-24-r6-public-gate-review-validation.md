## 3. 登录与保存路径复验

以游客身份计算完成、结果留在页内，再走保存全链路：

| 步骤                    | 实测结果                                                                |
| ----------------------- | ----------------------------------------------------------------------- |
| 游客点「保存本人资料」  | 打开真实登录对话框；**写入请求数 = 0**（未自动保存）                    |
| 页内注册（新账号 id=1） | 成功；创建后**未自动保存**（唯一写入为 `POST /api/auth/register`）      |
| 登录后草稿与结果        | 按治理规范保留当次草稿/结果，不自动导入档案                             |
| 点保存 → 差异确认       | 打开「保存本人档案」对话框，展示原表达 / 新表达 / 规范化公历 / 转换规则 |
| 差异确认内容            | 新增出生日期：公历 1990年6月15日 → 规范化 `1990-06-15`                  |
| 个人数据同意            | 需单独勾选「我确认这是本人的出生日期，并同意按当前告知长期保存」        |
| 未勾选时确认按钮        | 禁用（`disabled=true`）                                                 |
| 勾选并确认后            | 唯一写入 `PUT /api/self-profile`；对话框关闭                            |

| **保存是否产生历史**    | **否**（`historyWithBirthInputCount: 0`）                               |

**结论**：保存必须由用户显式触发、经差异确认与个人数据单独同意；
保存「本人资料」不产生结果历史，与契约「保存资料与保存结果分离」一致。

## 7. 格式门禁阻塞（本轮未达成项）

计划 `must` 要求「修复 pre-push 全仓 Prettier 门禁，使 `npx prettier --check .` 通过」，
但**该目标在本计划 scope 内不可达**：

| 项                                  | 值                                                                                       |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| `npx prettier --check .` 失败文件数 | 13（执行 `allowed_paths` 内格式化后剩 **12**）                                           |
| 在 `allowed_paths` 内、已修复       | 1：`docs/product/evidence/bazi/bazi-source-ledger.md`（仅空白/表格对齐，内容字节级不变） |
| 超出 scope、无法修复                | 12                                                                                       |

其中：

- `components/auth/AuthForm.vue` 命中 **`forbidden_paths`** 的 `components/**`；
- 另外 11 份命中 **`known_dirty_files`**：
  `docs/audits/**`（2）、`docs/validation/2026-09-21-*.md`（7）、
  `docs/validation/2026-09-24-tool-copy-residual-convergence-validation.md`、
  `docs/validation/2026-09-24-zeji-weight-boundary-visibility-validation.md`。

这 12 个文件全部在 commit `806dd32` 中提交且已被推送到 `origin/codex/foundation-rebuild`，
即**格式债务属于已推送基线**，而非本轮工作区新引入。

计划同时规定（`must_not`）「不使用 Prettier --write 改写未纳入本任务的业务源码或历史文档」，
且 `scope.notes` 明确「执行器不得顺手格式化整个工作区」。
因此执行器**未**格式化这 12 个文件，也**未**通过修改 `.prettierignore`
或放宽 hook 来制造门禁通过——后者正是计划 `must_not` 所禁止的「掩盖问题」。

**实际影响**：`.githooks/pre-push` 会在推送时因格式检查失败而拒绝，
`docs/product/README.md`、Bazi 台账与 GAP-BZ-007 记录所在分支**当前无法通过 pre-push**。
解除需要一个把上述 12 个文件纳入授权范围的计划（或单独提交一次纯格式修复）。

`docs/product/README.md` 与 `docs/validation/2026-09-21-r5-gap007-accepted-limitation.md`
经检查本就符合 Prettier，无需改动。
