## 7. 本轮建立的不变量（后续不得放宽）

1. **六段 DOM 顺序与段名固定**：`Ⅰ工具说明 / Ⅱ本次操作 / Ⅲ核心结果摘要 / Ⅳ通俗解释与详细结果 / Ⅴ依据与范围 / Ⅵ本次结果操作`，Ⅳ 不得简写为「详细与解读」（已有测试断言段名数组）。
2. **状态三重编码**：四类状态横幅必须同时有文字 + 图标 + 色相；图标 `aria-hidden`，语义由文字承担；stale 与 candidate 同时成立时以 stale 为准（图标 `↻`）。
3. **五行构成只做字面统计**：只列出现次数、不使用百分比/比例、不用「缺某行」措辞，并必须写明不代表旺衰、强弱、平衡与否；跨节时只统计唯一确定的日柱两个字。
4. **新增全局类必须同批写入 `docs/design/design-system.md`**；颜色一律 `color-mix`，禁止 `rgba()` 与 `bg-x/10`。
5. **窄屏与放大字体**：三柱一览按可用宽度自适应（窄屏/200% 自动转纵排）；长标签（等级 chip）必须可折行，任何 `nowrap` 都需先过 320px + 200% 实测。

## 8. 验收后追加修复（R5-C-F3：授权账号点入口链接仍被围栏拦下）

**现象**（用户真机反馈，2026-09-15）：登录「验收账号」后从首页点「八字（内部验证）」卡片，仍然落到 `/tools/status?tool=bazi`，显示「功能整理中」。

**复现与定位**（agent-browser + curl，均为整页/软导航两条路径对照）：

| 路径                                 | 实测结果                                          |
| ------------------------------------ | ------------------------------------------------- |
| 匿名整页加载 `/tools/bazi`           | 302 → `/tools/status?tool=bazi`（正确，失败关闭） |
| 已授权 cookie 整页加载 `/tools/bazi` | 200，正常渲染（curl 对照，服务端播种有效）        |
| 登录后点卡片（软导航）               | ❌ `/tools/status?tool=bazi`（缺陷）              |
| 登录后点顶栏链接（软导航）           | ❌ 同上                                           |

**根因**：`middleware/tool-availability.global.ts` 客户端分支只认 SSR 播种的 `tools:internalAccess`，未见播种即失败关闭；而**登录是纯客户端动作**——初始 SSR（`/`）时用户还是匿名，中间件根本没有为工具路由播种，于是「已授权账号」在软导航下必然被拒。只有手输 URL 整页加载才能进入，入口链接等于不可用。

**修复**（同批两处）：

1. `middleware/tool-availability.global.ts`：未见播种时不再直接拒绝，而是**整页重取同一路径**（`navigateTo(to.fullPath, { external: true })`）由服务端在真实请求上重新裁决；水合期仍失败关闭（避免「服务端渲染了页面却没播种」导致刷新死循环）。裁决权始终在服务端，客户端不放行任何未知值。
2. `layouts/default.vue` / `pages/index.vue`：开发期入口（`import.meta.dev`）追加登录态门，匿名不再看到「（内部验证）」入口——否则匿名用户点进去必然撞墙。两文件不在 R5-C 计划 `allowed_paths` 内，属开发期入口缺陷修复。

**回归测试**：`tests/middleware/tool-availability.test.ts` 由 7 例扩到 11 例，新增「登录后点入口链接可用（整页重取并保留完整路径）」「水合期未见播种失败关闭」「播种为拒绝时不重取」「退出登录后不再复用旧播种」。其中最后一条同时堵住一个既有隐性缺口：播种值代表播种那一刻的会话权限，退出后不得继续复用。

**修复后实测**（2026-09-15 同一 dev 服务器）：
