## 1. 验收目的与边界

P1 的目标是确认移动端反馈是否具有可定位的根因，并建立后续收缩或修复的真实浏览器证据，不是为了生成占卜结果或验证传统来源。

- 环境：本地 Nuxt 开发服务、Codex 内置浏览器，2026-09-01。
- 数据边界：创建独立浏览器页进行检查；未输入测字、姓名、出生信息或事项，未提交表单，未生成结果，未调用保存接口；原有用户档案标签页未修改。
- 页面缩放边界：浏览器环境实际最高只支持 `3x`。因此本记录不能宣称已通过 500% 缩放；500% 真机或完整浏览器可访问性验证留给后续移动端专项。
- 范围边界：`/tools/ziwei`、`/tools/hehun`、`/tools/meihua` 继续是 P0 hidden 路由，只能验状态页跳转，不作为本次公开工具组件样本。

## 3. 未测项与不夸大原则

1. `cezi`、`name-test`、`bazi`、`guming`、`yijing` 的结果生成会触发既有自动保存。未获专门测试档案授权时，本次不生成任何结果，因此不把结果区、长内容动画或评分展示写成已浏览器验收。
2. P1 识别的首页标题、CTA、择吉日历等其他移动风险仍由后续移动端专项逐项验证；本记录不把“未在此样本复现”写成“已修复”。
3. P1 没有核验任何传统典籍、民俗或算法来源。P1.2 的 `source_status` 仍以账本为准，不能因浏览器测试而提高为已核验来源。

## 4. 产品决定与阶段结论

用户已接受以下决定：

1. 遗弃全部工具页现有的“注/算法溯源”UI，不以 CSS 修补、信息图标、抽屉、弹窗或未核验外链替代。
2. 后续若建立来源能力，只能在人工核验后以结构化来源注册表或方法/边界页面承载；本次不实现。
3. P1 账本中 `downgrade` 的 9 个公开工程评分展示、`hide` 的生肖逐月运势，以及称骨默认输入缺口，进入下一阶段的公开真实性收缩范围。

据此，P1 的审计、原子账本、浏览器根因复验和用户决策确认均已具备。P1 标记为 `Accepted`。这不意味着公开内容已经收缩、自动保存已经治理、移动端已经整体通过或项目可以发布；这些工作分别由后续阶段完成。
