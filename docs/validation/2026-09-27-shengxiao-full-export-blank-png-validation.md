## 1. 结论摘要

已公开生肖页「保存本次结果图片」此前产出的 PNG 为**整张空白**（尺寸正确、只有画布底色）。本计划先在隔离生产预览中真实复现该缺陷，再把完整结果卡的离屏方式改为与八字一致的「0 尺寸 stage 裁剪」（最小源码改动，仅 `components/tools/shengxiao/VerifiedResult.vue`），修复后双轨导出的两张真实 PNG 均有内容、字段齐全、隐私边界不变；七项工程门禁全部 exit 0。本记录不回写历史审计原文。

## 3. 根因

与《八字图片导出双轨收敛验证记录》（`2026-09-27-bazi-export-convergence-validation.md`）§3 定位的根因相同：该版本 html-to-image 克隆节点时不把 computed 的 `left: -100000px` 归零，`useExportImage` 传入 `toPng` 的 `style` 覆盖不生效，内容被画到 foreignObject 视口之外，产物尺寸正确但整张空白。生肖完整结果卡沿用同一种负偏移离屏方式（前轮计划中该文件在 forbidden 清单，故未随八字一并修复）；其隐私文化卡片是可见卡片，不受影响。

## 4. 最小代码修复

`components/tools/shengxiao/VerifiedResult.vue`（唯一源码改动）：

1. 完整结果卡外包一层独立离屏舞台 `.verified-result__export-stage`：`position: absolute; top/left: 0; width/height: 0; overflow: hidden;` + `aria-hidden="true"`——「不可见且不占布局」由这个不被克隆的父容器承担；
2. 卡片自身 `.verified-result__export-card` 的 `left: -100000px` 改为 `left: 0; top: 0`，保留 `width: 640px`、固定版式、原字段顺序与来源入口；
3. `ref="resultCardEl"` 与 `data-result-card` 保持在卡片自身；stage 不是传给 `useExportImage` 的目标，裁剪属性不进入克隆根；
4. 隐私文化卡片与交互结果三张卡结构未动；页面接线、契约字段、按钮旁出生日期风险提示、两个文件名与双轨导出独立状态均未改。

## 8. 证据口径与环境限制（如实记录）

- **导出产物捕获方式**：浏览器内对 `HTMLAnchorElement.prototype.click` 加证据钩子，记录 `useExportImage` 创建的真实下载锚点（文件名 + dataURL）；字节与用户保存的文件一致，html-to-image 真实运行，无 mock。
- **rAF 垫片**：本会话宿主渲染面不驱动 `requestAnimationFrame`（`document.hidden === false` 但帧冻结），首次导出停在「导出中...」。导出前在页面内注入 rAF→setTimeout 垫片，属**测试环境仪表化**，不是产品改动；导出字节由 html-to-image 在真实浏览器中产出，垫片只解除调度冻结。
- **页面截图**：修复前成功截取 1 张对照（`before-page-success.png`）；修复后页面截图在当前环境超时（同一渲染面限制），页面证据以两张真实 PNG、DOM 几何与像素测量承担。
- **单测边界**：单测只锁定结构关系（导出目标是 `data-result-card` 卡片自身而非 0 尺寸 stage、stage 的 aria-hidden、隐私字段边界、stale/无结果无导出入口）；PNG 非空白由真实浏览器证据承担，不以 mock 成功冒充。
