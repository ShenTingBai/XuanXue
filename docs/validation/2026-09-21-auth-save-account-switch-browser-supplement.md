## 1. 补验背景

上一计划的代码、自动化门禁、游客计算与退出清理已通过，但 Codex 裁定为 **partial**，原因是两条链路未走查：

2. A→B 换号隔离（账号 B 不得看到或复用账号 A 的档案、草稿、结果、历史、保存意图与权限）。

本计划只补浏览器证据，不修改任何产品代码。

| -------------------------- | --------------------------------------------------------------------------------------------- |
| 游客打开首页               | 顶栏「未登录 登录」；导航仅「生肖」                                                           |
| 进入 `/tools/shengxiao`    | 站内 SPA 导航，无任何 API 请求                                                                |
| 输入 1990-06-15 + 确认年龄 | 表单可提交                                                                                    |

| 点击「保存本人资料」       | 打开真实 `AuthDialog`（角色 dialog，标题「登录」）；草稿 1990 与结果区仍保留，保存意图未丢失   |
| 注册并登录账号 A           | `POST /api/auth/register` → 200；随后仅 `GET /api/self-profile/summary` 与 `GET /api/self-profile`（**读取**），无任何写入 |
| 差异确认弹层               | 显示「新增出生日期」：原表达（无）→ 新表达 公历 1990年6月15日；规范化公历 1990-06-15；转换规则 `lunar-javascript 1.7.7 / self-profile-date-v1`；告知版本 2026-09-09 |

| 单独点击确认保存           | `PUT /api/self-profile` → 成功；**连点两次只产生一次写入**（防重复生效）                      |
| 保存后档案状态             | summary `exists: true`、`hasBirthDate: true`、`version: 1`；完整读取返回 `solarDate: 1990-06-15` 与 `raw: { calendar: 'solar', year: 1990, month: 6, day: 15 }` |
| 二次打开保存弹层           | 显示「出生日期保持不变」+「日期没有变化，无需保存。」，确认按钮禁用；无新增写入请求            |

**结论**：登录成功本身不保存；只有勾选并单独点击确认后才写入出生日期；生肖结果与历史零服务器持久化。
