## 1. 基线与问题

改动前，“存为图片”按钮只把 `VerifiedResult.vue` 的 `privacyCardEl` 传给 `useExportImage()`。这个目标刻意不含出生日期，但按钮名称没有说明导出范围。组件测试核对了传入的 DOM 和文件名，组合函数测试模拟了 `html-to-image` 与下载链接；这些证据不能证明真实浏览器产生可打开的 PNG。

本轮开始时，上一轮“依据与范围”收敛的三个源码/测试文件和验证记录仍未提交，另有 `.zcodeignore`。本轮保留这些既有改动，没有回滚或提交。

## 2. 本轮实现

| 导出动作         | 目标                  | 文件名                 | 隐私边界                                               |
| ---------------- | --------------------- | ---------------------- | ------------------------------------------------------ |
| 保存隐私文化卡片 | `[data-privacy-card]` | `生肖隐私文化卡片.png` | 不含完整出生日期、账号或档案标识                       |
| 保存本次结果图片 | `[data-result-card]`  | `生肖完整结果.png`     | 含本次公历出生日期；按钮旁直接提示只建议保存到本人设备 |

完整结果卡是独立的固定宽度图片模板，包含公历与农历日期、干支年、生肖、对应地支、农历年公历起止、时区、规则版本和页面 Ⅳ 段来源入口说明。不截图整个页面，也不包含导航、输入控件、账号区、保存按钮或来源清单全文。两条路径分别持有导出状态，避免一个按钮成功后另一个按钮也显示“已保存”。

`useExportImage()` 在克隆节点上归零离屏定位；只有得到 PNG data URL 才触发下载链接。错误会返回失败并恢复忙碌状态。这里的返回值仍不能证明浏览器已将文件写入磁盘。
