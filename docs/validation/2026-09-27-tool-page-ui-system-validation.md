## 4. 通用规范矩阵（写入 `design-system.md` §4.2b）

### 4.1 三层判据

| 层         | 判据                                       | 是否跨工具强制       |
| ---------- | ------------------------------------------ | -------------------- |
| 共享层     | 与工具领域无关的骨架、承载、状态、可访问性 | 强制                 |
| 条件适用层 | 由该工具的产品契约决定该能力是否出现       | 出现时强制用共享实现 |
| 工具专属层 | 由该工具领域内容与契约决定                 | 禁止跨工具强制       |

### 4.2 共享层清单（9 条规则）

页面外壳唯一、分节与标题、段序、正文与卡片层级、状态反馈、按钮分工、依据与范围呈现、响应式与焦点、页面根级样式挂载。

每条规则都写明**实现入口（真实存在的组件/类名）**、**禁止的重复实现**、**验收方法**。例：卡片层级明确「表单容器 `card-paper-solid rounded-xl p-6 sm:p-8`、结果与信息卡 `card-warm rounded-xl p-6 sm:p-8`、禁止固定 `p-8`、验收要求为 320px 下正文可读且无横向溢出」。

### 4.3 条件适用清单（6 项能力）

| 能力                       | 启用条件                          | 不该出现的情形                          |
| -------------------------- | --------------------------------- | --------------------------------------- |
| 输入承载卡（单卡）         | 工具存在当次个人输入              | 纯公共浏览内容、状态页                  |
| 年龄声明                   | 产品契约要求年龄门禁的个人计算    | 无个人输入的工具、纯文化浏览段          |
| 依据折叠壳                 | 页面有可折叠的详细来源 / 规则台账 | 会改变适用性判断的内容（§4.1 折叠边界） |
| 档案带入                   | 契约允许使用本人档案              | 禁止暗中读取档案                        |
| 保存 / 历史 / 导出         | 契约与工具目录策略允许            | `historyPolicy: disabled` 或未公开工具  |
| `marginal-toggle` 轻量折叠 | 卡片内轻量次级内容                | 已落地共享壳的依据折叠                  |

「年龄声明」条目直接写入计划 `rules.must` 第 4 条的判据：**契约未要求年龄门禁的页面不得添加年龄勾选**，与数据生命周期规范 §5.4「公开文化内容无需年龄确认即可浏览」一致。

### 4.4 工具专属说明（5 条）

段数、输入字段、结果图形与卡片、公共文化内容、来源清单内容——逐条写明「不跨工具强制」，并明确：来源清单的条目与条数由该工具来源台账决定，共享的只是折叠壳。

### 4.5 未来工具页接入检查表（8 项）

契约能力与段序、共享外壳、输入/结果/空态层级、来源边界、年龄/隐私条件、键盘与缩放、真实浏览器状态验收、例外记录。

填写规则：每项只能填「通过 / 不适用（写明理由）/ 待补（写明证据计划）」，不得留空；例外必须有验收证据或明确的证据计划。

### 11.1 修正的事实与依据

原设计系统 §4.2b「条件适用清单」把「保存 / 历史 / 导出」写为一行合并判据：启用条件为「契约与工具目录策略允许（`approved` + `public` + 对应历史策略）」，「不该出现」为「`historyPolicy: disabled` 或未公开工具」。该写法把**本地图片导出**错绑到 `historyPolicy`，与同一时点的代码与契约事实冲突：

- `constants/tool-catalog.ts` 中 `canExportTool(id)` 等价于 `isToolPubliclyAvailable(id)`（`approved` + `public` + `enabled`），**不含** `historyPolicy`；历史读取与创建才分别绑定 `canReadHistory` / `canCreateHistory` 与 `historyPolicy`。
- 生肖 `historyPolicy: disabled`（生肖契约 §6.4「不保存原则」），但 `canExportTool('shengxiao')` 为真，`pages/tools/shengxiao.vue` 提供隐私文化卡片与完整结果图片双轨本地导出（生肖契约 §6.5），并有经差异展示与单独确认的「保存本人资料」流程（生肖契约 §6.3；保存对象是本人档案的出生日期，不是结果历史）。
- 八字契约 §23 对三者各自规定：登录用户主动确认后保存不可变快照、历史读取与重算边界、本地导出的简洁 / 完整双版本。

原记录 §4.3 摘要表与 §5「治理规范 §20.2」行的合并口径与原 §4.2b 同源，按「不改写历史记录」原则保留原文，以本节与修订后的设计系统 §4.2b 为准。

### 11.2 修正后的三项独立判据（设计系统 §4.2b「条件适用清单」已同步拆分）

| 能力                  | 政策来源                                                         | 与 `historyPolicy` 的关系           |
| --------------------- | ---------------------------------------------------------------- | ----------------------------------- |
| 本人档案显式保存      | 档案与数据生命周期契约 + 该工具契约；用户主动操作并单独确认      | 无关；不等于保存结果                |
| 结果历史（读取/创建） | `canReadHistory` / `canCreateHistory` 与工具目录 `historyPolicy` | 直接绑定；`disabled` 即无服务端历史 |
| 本地图片导出          | 该工具契约导出章节 + `canExportTool`（公开可用状态）与隐私约束   | 无关；`disabled` 不是导出禁令       |

`historyPolicy: disabled` 只禁止**服务端结果历史**，不自动禁止浏览器本地导出，也不自动禁止另行同意的本人档案保存。未公开工具当前不出现公开导出与历史入口，属「当前公开入口未开」而非「能力永久禁止」；未来接入按当时工具目录状态与对应契约验收。设计系统「未来工具页接入检查表」第 5 项与 §10 模板文案经核对不含同类错误，未改动。
