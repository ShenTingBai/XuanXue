## 1. 本轮范围与动因

## 5. 浏览器覆盖边界（未达成的部分）

**择日页在生产构建下仍不可达，未能取得页面级浏览器证据。** 已实测确认根因：

1. 择日 `exposure: internal`，中间件 `middleware/tool-availability.global.ts` 会重定向到状态页；
2. 唯一例外是 `computePolicy === 'enabled'` **且**服务端内部验证白名单授权当前账号；
3. 但 `nuxt.config.ts:155` 设定 `/tools/**` 为 `ssr: false`，仅 `/tools/bazi` 例外为 `ssr: true`
   ——注释中已说明：`ssr: false` 时围栏只在客户端运行，既不做服务端重定向也不播种授权结果，
   客户端「未知即失败关闭」使授权账号同样被重定向（R5-B 已实测），**白名单通道对 zeji 不可用**。

本轮实际执行：以生产构建启动预览（`DB_PATH` 指向临时库、`XUANXUE_INTERNAL_TOOLS=zeji:1`），
通过真实浏览器注册测试账号（id=1，与白名单一致，`/api/auth/me` 确认会话有效），
访问 `/tools/zeji` 仍被重定向到 `/tools/status?tool=zeji`。使 zeji 可达需要修改 `nuxt.config.ts`
的 `ssr` 规则，该文件不在 allowed_paths 内，本轮未改。

### 5.1 已取得的替代实测证据

`Masthead` 是 12 个工具页共用的报头组件，其 `.meta-text` 样式对择日与生肖完全一致。
在可达的生肖页（同一组件、同一 CSS）注入本轮新增的 47 字 meta 串，实测其排版承载能力：

| 视口宽度 | 文本裁切 | 横向溢出 | `text-overflow` | 换行 |
| -------- | -------- | -------- | --------------- | ---- |
| 1280     | 无       | 无       | clip            | 正常 |
| 920      | 无       | 无       | clip            | 正常 |
| 414      | 无       | 无       | clip            | 正常 |
| 360      | 无       | 无       | clip            | 正常 |
| 320      | 无       | 无       | clip            | 正常 |

`.meta-text` 无 `nowrap`/`ellipsis`/`overflow:hidden`，`.meta` 容器 `flex-wrap: wrap`，
因此长 meta 串在窄屏正常折行、不截断（实测 `scrollWidth === clientWidth`）。

**该证据只证明共用报头能承载该文案，不等于择日页面已通过浏览器验收。**
